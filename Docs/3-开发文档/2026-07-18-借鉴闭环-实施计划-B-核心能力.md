# 借鉴闭环核心能力 Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立模板中立的单根借鉴区、两类卡片、权限与状态合同、唯一执行 Skill 和可安全复用的来源接入流程。

**Architecture:** `借鉴区/` 只承载来源版本卡、事项卡和本地忽略缓存；rules、skill、workflow 各写一种事实。Skill 是唯一面向操作者的入口，并调用模块化 PowerShell 捕获执行器落实 Git/local/web 安全语义；不引入全局数据库/派生索引、hooks、daemon 或自动刷新服务。

**Tech Stack:** Markdown、受限 YAML frontmatter、PowerShell 5.1、Git、SHA-256、现有 Q1-Q7/L1-L4/A-B-C 治理。

> **WinPS 不变量：** 本计划所有新建或修改的 `.ps1` 在首次执行前及每次语义编辑后都必须幂等归一化为 UTF-8 BOM，并立即运行 `check-winps-encoding.ps1`。

- [x] **Step 3: 锁定三类来源行为**

- Git：生产 façade 只接受净化 HTTPS locator，拒绝 userinfo、敏感 query、非字面 ref。`git.ps1` 接受内部 runner 接口，但 façade 不暴露 runner/transport 注入参数，始终构造 `git-runner.ps1` 的生产 runner。契约分两层：① command-plan 单测精确断言 `GIT_TERMINAL_PROMPT=0`、禁 system/global config、空 credential helper、禁 hooks/LFS/filter/submodule/递归和固定 ref；② process 集成用测试专用 runner 把 fixture HTTPS operand 映射到本地 bare repo，仍调用真实 `git.exe`，并在临时 HOME 预置会写 marker 的恶意 global config/hook/filter，断言 marker 均未触发且 commit/tree/object format 固定。测试 runner 只直接注入 helper，不能穿透生产 façade。
- Local：`source-before` 属于 input 且先于 staging；同卷 staging；排序 SHA-256 manifest；四次 manifest 与 stored bytes 必须一致；M0/M1 源身份逐项相同、M0/M2 复制身份逐项不同且单链接、M2/M3 move 身份逐项相同；链接、reparse point、静默漏读或复制中变更均失败。
- Web：执行器只接收已授权下载得到的原始响应字节和显式响应元数据，不自行联网；按原始字节哈希，不把解码文本替代 raw bytes。

- [x] **Step 4: 锁定原子性、幂等与 P4t 闸门**

candidate validator 在晋升前校验卡片/缓存/权限表；staging 与最终目录必须同卷。相同 fingerprint 重试复用既有 capture，不同 fingerprint 新建；无效输入、validator 失败或标准路径 P4t fixture 返回 `5/10` 时不得留下新的正式 capture，允许保留被忽略 staging 并报告位置。顺序固定为 candidate 校验 → 晋升前根 P4t=0 → 原子移动 → 晋升后根 P4t=0；后验失败必须把本次新目录原子移回 staging。只有两次 P4t 均为 0 才输出 ready。
