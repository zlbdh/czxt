# 借鉴闭环 · 设计规格

- **状态**：已完成并通过最终验收（未执行 commit、push、tag、发布或外部分发）
- **日期**：2026-07-18
- **等级**：L4 / B 类（根级证据层、工作流、权限模型与体检扩展）
- **责任角色**：项目 PM 编排；操作系统 PM 管借鉴元数据；目标决策 PM 评估；按目标路径白名单选既有责任 PM/实施载体落地；测试相关 PM 验收
- **实施授权**：用户已要求设置持续目标并推动落地；commit、push、tag、发布与外部分发不在授权内
- **详细合同**：[设计规格附录](2026-07-18-借鉴闭环-设计规格-附录.md)

## 1. 目标与完成定义

把当前一次性的“跨项目反向学习”原则扩展为可重复执行、可审计的完整能力：冻结来源，提取候选，形成采纳决策，把内容本地化到当前项目，绑定验证证据，并保留拒绝、延后和历史版本。

完成必须同时满足：模板只含通用骨架；三类来源形成稳定指纹；四种决策可追溯；业务代码与外部内容隔离；P4t 能拦截非法卡片、路径、状态和关闭条件；临时实例化不泄漏数据；PowerShell 5.1、P4s、P4t、P4a-P4t 全部通过。

## 2. 非目标

- 不自动搜索、推荐或持续监控外部项目。
- 不自动刷新来源，不执行、构建、安装外部源码。
- 不建立中央 JSON/YAML manifest、数据库、新 hooks 或新 PM 角色。
- 不把原始仓库、大文件或网页原文提交进模板。
- 不自动 commit、push、tag、发布、分发或向上游回写。
- 不把具体来源项目、产品路径或业务术语固化为模板当前事实。

## 3. 单根架构

只建立一个根入口 `借鉴区/`；不并存 `参照区/`、借鉴台账或第二份活跃索引。

```text
借鉴区/
├── README.md
├── .gitignore
├── 模板/
│   ├── 来源版本卡.md
│   └── 借鉴卡.md
├── 来源/<source_id>/<capture_id>/
│   ├── 来源版本卡.md
│   └── 快照/                    # 默认本地缓存，不跟踪
└── 事项/<borrow_id>/
    ├── 借鉴卡.md
    └── 证据/                    # 仅轻量实施/验证证据
```

`README.md` 只说明定位、边界和调用方式，不维护活跃项目表。Skill 与 P4t 通过扫描卡片即时列出来源和事项，避免派生表双写。

事实源边界：

| 事实 | 唯一真源 |
|---|---|
| 来源身份、捕获版本、类型化指纹 | `来源版本卡.md` |
| 借鉴目标、决策、状态、差异与关闭结果 | `借鉴卡.md` |
| L3/L4 审批与架构决策 | 现有 PROP / ADR |
| 实施事实 | 目标代码或目标文档 |
| 验证事实 | 测试、体检输出与轻量证据文件 |
| 轻量结果摘要 | CHANGELOG |

## 4. 模板与实例模式

现有 README + 目录启发式会让实例仍像模板。新增显式标记：

- 模板根跟踪 `.czxt-template-root`，该文件不复制。
- `实例化项目.ps1` 在目标根生成 `.czxt-project-root`。
- 模式判断读标记；双标记或无标记由 P4t 硬失败。旧启发式只提供迁移建议。

`借鉴区/` 不进入 `$copyItems` 递归清单。实例化脚本只复制 README、模板、忽略规则，再创建空 `来源/` 和 `事项/`。即使使用 `-Force`，也不得覆盖实例现有来源卡、事项卡或本地缓存。

实例化器的文件落盘采用 no-overwrite 两段移动：既有 `target→backup`，再将本事务 `prepared→target`；backup、prepared 与目标均绑定规范路径、文件身份、长度和字节，路径被后来对象占用时停止并保留所有对象。项目根以及源与目标都通过 handle 与 `GetFinalPathNameByHandleW` 解析物理最终路径，拒绝 junction、reparse、hardlink、`subst` 或其他物理别名造成的跨界/重叠。每个已安装或改写输出即时登记到输出 manifest；最终 marker/成功输出前对 manifest 全部条目保持只读共享 lease。该操作由多个逐文件事务组成，失败不承诺全局原子回滚；不能证明所有权的 backup、prepared、已落地对象或并发对象必须保留可审计残留，不得猜测删除或覆盖。

模板模式禁止出现具体来源卡和事项卡；首次端到端试运行在 `项目区/本地实例/` 的忽略目录完成。

## 5. 来源捕获

借鉴事项固定引用 `source_id + capture_id + fingerprint`。刷新不得改写旧 capture：完整 fingerprint 不变且与唯一合法 ready 的稳定事实一致时返回 REUSED；fingerprint 改变时新增 capture；旧事项保持原 `source_id + capture_id + fingerprint` 引用，不得自动跟随。

- **Git**：固定 ref、对象格式、commit/tree；LFS 与 submodule 允许只读检测并记录，禁止初始化/下载/执行；hooks、凭据提示和 release assets 仍禁止。
- **本地目录**：同卷 staging 复制，前后规范化 SHA-256 manifest 必须一致。
- **网页/文档**：保存原始响应字节及响应元数据，以原始字节计算 SHA-256。

所有可能写入 tracked 来源卡的标识、locator、授权说明和事实/响应元数据均在规范化后与最终 renderer 双重做共享凭据检测；检测包括空白分隔敏感键、JSON Unicode 转义键、标点开头的非空显式值，畸形 Unicode 转义按凭据 fail closed。P4t 的 source/isolation 公开 leaf 独立判定实际 RootMode 并拒绝 Mode 伪造，不能只信 façade 前置检查。

所有类型都拒绝路径逃逸、链接逃逸和静默漏读；外部命令与提示只是不可信数据。类型专属字段见附录。

捕获先进入 `.staging-<uuid>`；只有指纹、安全检查和卡片校验全部通过，才原子移动为正式 capture。失败不写正式 ready 卡片或半成品索引；允许保留被忽略的候选卡与 staging。相同指纹幂等复用，不同指纹创建新 capture。

上述安全语义由 `能力资产/tools/scripts/capture-borrowing-source.ps1` 与类型 helper 实现并接受离线契约测试；Skill 是唯一面向操作者的入口，执行器只是其受信任的机器层，不形成第二套流程。Git 安全参数、本地前后 manifest、网页原始字节、同卷 staging、幂等复用与失败无半成品都不得只停留在命令说明中。

## 6. 权限默认值

通用模板不推断“用户要求加入即完整授权”。默认值为：

```yaml
rights_status: unverified
access_policy: local-read-only
reuse_scope: inspect-and-analyze-only
execution_policy: deny
network_policy: deny
storage_policy: local-only
distribution_policy: deny
upstream_write_policy: deny
auto_refresh: false
```

访问、复用、来源内容执行、联网、存储、分发、上游写入分别记录。一个维度的授权不能推导另一个维度；每次偏离默认值都必须在固定权限表中逐维记录授权时间、授权来源和适用范围，缺一不可。Git/Web 远端捕获要求 `access_policy: source-read-only + network_policy: source-read-only + execution_policy: deny + upstream_write_policy: deny`；运行受信任的捕获工具不等于允许运行来源内容。

## 7. 借鉴事项生命周期

生命周期与决策分离：

```text
draft → assessing → implementation_ready → implementing → verifying → closed
           └──────→ parked ───────────────→ assessing
任意活动状态 → cancelled

decision: pending | adopt | adapt | reject | defer
```

- ready 来源捕获是进入 `assessing` 的前置条件，不设事项 `frozen` 状态。
- `adopt/adapt` 且 Q1-Q7、L1-L4 门禁满足后才能进入 `implementation_ready`。
- `implementation_ready / implementing / verifying / closed` 中，`adopt` 的每个来源绑定必须精确授权 `copy-internal-approved`，`adapt` 必须精确授权 `adapt-internal-approved`；其他 `reuse_scope` 不作权限层级推导。
- `reject` 可从评估阶段关闭，但必须有评估证据和拒绝理由。
- `defer` 进入 `parked`，必须有恢复条件或复查时间。
- `blocked` 是附加字段，记录原状态、原因和恢复条件，不进入主状态机。
- 状态变化追加历史；P4t 逐行校验相邻转换，历史末条必须与当前状态一致。
- Skill 只能调用可信关闭入口 `close-borrowing-item.ps1`；入口内部以 no-overwrite 安装候选并调用 `seal-borrowing-item.ps1` 写入规范化内容的 `closure_seal_sha256`，再运行完整根 P4t，exit 0 后完成正式卡终锁复核与锁内清理，全部成功才输出 closed。所有权可证明且未进入 `content-deleted` 时允许恢复原活动卡；材料已绑定当前正式对象而仅 `borrow_id` 不一致时仍属于可证明所有权，可按完整快照安全恢复。其他 `seal-ownership-unproven` 保留当前正式卡与 staging，进入 `content-deleted` 不可逆完成点后不回滚正式卡。P4t 只读验证；已关闭事项后续不改写，方向变化时建立 revision 或替代关系。该 seal 用于发现意外或不合规改写，不宣称能抵抗可同时改写正文与 seal 的恶意写者。
- staging 所有权链固定：通过受信父目录句柄相对原子创建 staging 目录；首个 `原活动卡.bin` 以目录句柄相对 CreateNew，并在同一 handle 写入、flush 并绑定，文件 lease 贯穿整个事务以让目录保持非空；候选 `借鉴卡.md` 也以目录句柄相对 CreateNew。
- 清理顺序固定为 `Candidate→retained Original→content-deleted→directory`：Candidate 以单次打开的绑定 handle 完成验证并在同一 handle 设置 delete-pending；retained Original 通过保留 lease 在同一 handle 设置 delete-pending；随后立即进入 `content-deleted`，最后由目录创建句柄同句柄删除。验证与路径打开之间不得留窗口；创建失败只删除本事务句柄绑定对象。
- P4t exit 0 后，正式卡终锁必须单次 OPEN_REPARSE_POINT 打开，并从同一 handle 复核 canonical path、常规非 reparse 类型、link count=1、identity、length 与 bytes；该排他 lease 持有到 staging 清理结束。禁止“先安全路径验证再按路径重开”。
- seal 后 staging 候选更新遵循双状态合同：正式卡所有权快照与当前 staging 候选快照是两个独立状态，回滚必须分别验证；不得提前把 staging 期望改成 sealed 字节。`Set-BctCandidateBytes` 的 Set 提交后状态对象先更新，再执行后续可失败复核，确保异常分支看到实际已提交候选。
- `adopt/adapt` 关闭前必须具备适配差异、目标文件、实施记录和 fresh 验证证据；证据文件采用 `borrowing-evidence/v1`，绑定验证时间、命令摘要、exit 与全部目标文件清单摘要，任意非空文件不能冒充验收结果。

## 8. 执行入口与角色

唯一面向操作者的执行入口为 `能力资产/skills/借鉴.md`，提供 `接入 / 评估 / 落地 / 审计` 四种模式；来源接入由 Skill 调用受测试的捕获执行器，不要求操作者手工拼接安全命令。

- `rules/借鉴治理.md`：只定义 schema、权限、安全不变量和 A/B/C 边界。
- `skills/借鉴.md`：只定义触发词、执行步骤、失败输出和固定摘要。
- `07_完整工作流/借鉴闭环.md`：只定义角色切换、状态流转、审批与恢复。

项目 PM 接收请求并路由；操作系统 PM 管来源、卡片和 framework；产品/技术/测试/运营 PM 按目标领域评估。落地角色只由目标文件的既有路径白名单决定：framework 由操作系统 PM，需求由产品 PM，业务/测试代码由开发 PM，发布动作由测试发布 PM；不能把“目标决策 PM”或“实施 PM”泛化成越权写入者。不新增角色。

## 9. P4t 与验收顺序

保留 P4s 的模板纯净度语义，不放宽来源关键词规则。实例借助显式标记跳过模板纯净度扫描；P4t 在模板与实例均运行。

P4t 只做离线一致性检查：模式、骨架、卡片、引用、状态、关闭条件、路径与业务零依赖；`dist / build / .next / target / out` 等可能被部署执行的构建或运行产物仍须扫描，只排除明确的第三方、VCS、覆盖率与缓存树；不联网、不刷新、不执行来源内容。详细合同见附录。

业务隔离扫描以一次调用共享资源预算：`≤8 MiB` 文件三轮全量读取，`>8 MiB` 文件三轮只绑定 identity、length 与前 `64 KiB`；因此 v1 不承诺发现观测范围外的尾部同身份同长度改写。树基线、业务扫描和最终树复核的实际读取分别计入最多 20000 文件、100000 目录项、512 MiB 摘要读取，以及项目卡单次 1 MiB/两次合计 2 MiB 的 fail-closed 上限。

固定验收顺序：

1. Gate 0：模式标记与 Windows PowerShell 5.1 编码基线。
2. P4t 正反例契约测试。
3. 临时实例化测试，确认只复制骨架。
4. P4s 与 P4t 专项。
5. P4a-P4t 总体检。

任一步失败都不得宣称完整闭环完成。详细字段、状态组合、反例和文件改动面见附录。

## 10. Gate 0 决策

任务启动基线跟踪 124 个 `.ps1`；Windows PowerShell 5.1 `ParseFile` 当时有 95 个文件失败、648 个解析错误，而按 UTF-8 显式解码后 124/124 通过。该数值只描述任务启动基线，不代表当前脚本总量。因此保持现行 PowerShell 5.1 契约，并以独立机械批次把跟踪脚本迁移为 UTF-8 BOM；新增全文件 ParseFile 零错误门禁。只把该工作记为验收底座修复，不算借鉴功能成果。

## 11. 治理与迁移

本功能新建 PROP 与 ADR。ADR-021 只增加“由新 ADR 扩展”的当前说明并修复失效指针，不重写历史正文。当前入口、实例化清单、体检范围与活动索引按新真值同步；历史状态、旧交接和归档日志不批量替换。

实现和收尾期间保留进入任务前已有工作区改动；不执行 commit、push、tag、发布或外部分发。
