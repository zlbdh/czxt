# ADR-002 · Move Application Code into the {{APP_REPO_DIR}}/ Subdirectory

- **Status**: Current
- **Date**: 2026-05-08
- **Decision maker**: zlbdh
- **Related**: — (structural change, not a PRD feature)

> ⚠️ **Current override notice (2026-06-15)**: `{{APP_REPO_DIR}}/` remains the application code repository. The `rules/` directory described here reflects May 2026; ADR-007 and ADR-029 subsequently evolved it into `操作系统/` + `能力资产/`.

## Context

Before 2026-05-08, the “{{PROJECT_NAME}}” project root, `D:\\WGKJ\\{{PROJECT_NAME}}\\`, had a **flat layout** with 22 top-level items: code (src/, public/, android/, dist/, node_modules/), 9 root configuration files, rules (rules/), documentation (Docs/), the proposal pool (确认改动/), APK archives (apk/), CI (.github/), and the entry point (README.md).

After viewing the file browser, zlbdh explicitly described it as “so cluttered” and asked to separate application code.

Options:

| Option | Description | Assessment |
|---|---|---|
| Keep it | Accept 22 top-level items | Repeated searching |
| Move to `code/` | Generic name | Neutral |
| **Move to `{{APP_REPO_DIR}}/`** | Matches the original design and the project instance | Selected |
| Move to `app/` | Short, but both it and `apk/` start with a | Slightly ambiguous |

## Decision

**Move all code and configuration into `{{APP_REPO_DIR}}/`**, leaving only documentation, rules, proposals, APK archives, and entry guidance at the root:

```
{{PROJECT_NAME}}/
├── {{APP_REPO_DIR}}/             ← Application code
├── rules/            ← AI rules
├── Docs/             ← Documentation
├── 确认改动/         ← Proposal pool
├── apk/              ← APK archives
└── README.md         ← Entry point
```

**14 items moved into `{{APP_REPO_DIR}}/`**:
- 5 directories: `android/`, `public/`, `src/`, `dist/`, `node_modules/`
- 9 configuration files: `.gitignore`, `package.json`, `package-lock.json`, `vite.config.js`, `tailwind.config.js`, `postcss.config.js`, `capacitor.config.json`, `index.html`, `build-apk.bat`

**Kept at the root**:
- `rules/`, `Docs/`, `确认改动/`, `apk/`, `README.md`

Follow-up correction on 2026-05-08: the remote Git repository root is `{{APP_REPO_DIR}}/`, so GitHub Actions must reside in `{{APP_REPO_DIR}}/.github/workflows/` to be pushed and activated in `zlbdh/{{APP_REPO_DIR}}`.

## Consequences

### Benefits
- The root shrinks from 22 items to about 6, with **clear responsibilities**.
- Rules (`rules/`) and code (`{{APP_REPO_DIR}}/`) are separate, reducing confusion during AI work.
- The layout can be **copied as a template for other projects**, organized as `项目名/` + `rules/Docs/{{APP_REPO_DIR}}/...`.

### Costs
- Run `cd {{APP_REPO_DIR}}/` before npm/npx commands:
  ```cmd
  cd /d D:\\WGKJ\\{{PROJECT_NAME}}\\{{APP_REPO_DIR}}
  npm install / npm run dev / npm run build / npm test
  ```
- `build-apk.bat` locates its directory through `cd /d "%~dp0"`; **all internal relative paths remain valid**. Only messages change, not logic.
- GitHub Actions resides at `{{APP_REPO_DIR}}/.github/workflows/build-apk.yml`. Workflow paths use `{{APP_REPO_DIR}}/` as the repository root and no longer use `working-directory: ./{{APP_REPO_DIR}}`.
- In Docs/Agent, `src/...` means “relative to `{{APP_REPO_DIR}}/`”; no per-reference prefix is needed.
- Redraw the README.md project structure diagram.

### Reconsideration
- **Trigger**: the {{APP_REPO_DIR}} layer makes navigation harder, for example because almost every command requires changing into it.
- **Reversal**: `mv {{APP_REPO_DIR}}/* .` + `rmdir {{APP_REPO_DIR}}`, reverse the `{{APP_REPO_DIR}}/.github/workflows/build-apk.yml` changes, rewrite the README.md structure diagram, and remove the `{{APP_REPO_DIR}}\\` prefix from operations documentation.
- **Data migration**: none; only file moves and documentation path substitutions.
- **Estimated reversal cost**: 30 minutes.
