# ADR-005 · Chat History Archiving (Add archived to chatMessages and Upgrade Dexie v1→v2)

- **Status**: Current (implemented after zlbdh approved PROP-002 on 2026-05-09)
- **Date**: 2026-05-09
- **Decision maker**: zlbdh / Mimi
- **Related**: F-203 / [PROP-002](../../../确认改动/已审批/已完成/PROP-002-2026-05-09-聊天历史归档.md)

## Context

The `chatMessages` table had no expiration or archiving mechanism. All user/AI conversations remained indefinitely; startup `loadSnapshot` loaded them all into `data.chatMessages`, and `HomeChat` rendered `slice(-4)`.

As records grow into the thousands:
- Startup deserialization becomes heavier.
- The home screen should show the latest 4 active messages without old messages mixed in.
- All history should still be retained, browsable, and recoverable from backups.

Options:
- A. Permanently delete messages beyond the latest 30 → loses data and conflicts with backup recovery. **Rejected**.
- B. Soft-mark an `archived` field, show the latest 4 of up to 30 active messages on Home, and allow browsing all messages. **Accepted**.
- C. Create a separate archivedChatMessages table → broader changes and two read/write schemas, with insufficient benefit. **Rejected**.

zlbdh added to B: **users must be able to browse chat history directly, not only through backups**. This expanded the original PRD with a “Past Conversations” Card and a full-screen ChatHistoryDrawer.

## Decision

**Add an indexed `archived` field (0|1) to chatMessages. Upgrade Dexie v1→v2 and use upgrade() to backfill existing records with archived=0.**

Details:

1. **Dexie v1 → v2**
   ```js
   db.version(2).stores({
     ...,
     chatMessages: 'id,createdAt,archived',  // Only change: add the archived secondary index
     ...
   }).upgrade(async tx => {
     await tx.table('chatMessages').toCollection().modify(msg => {
       if (msg.archived === undefined) msg.archived = 0;
     });
   });
   ```
   Keep the other 11 table schema strings unchanged. v2 must list every table to avoid losing them.

2. **Field semantics**
   - `archived: 0` = active, visible on Home, default.
   - `archived: 1` = archived, hidden on Home, still browsable in Profile's “Past Conversations” drawer.
   - Use integers 0|1 because IndexedDB does not index booleans.

3. **Trigger archiving immediately after each new message is stored**
   - Inside useAppData's `addChatMessage(input)` action:
     - After addRecord completes, query `db.chatMessages.toArray()`.
     - Count records with `archived !== 1`, the active count.
     - If active >30, mark the oldest `(active - 30)` records archived=1 in one pass.
   - Do not archive in loadSnapshot, to avoid silently bulk-modifying user data.

4. **Data flow**
   - `loadSnapshot`: `db.chatMessages.toArray()` returns everything, including archives; components filter it.
   - Home `recentChat`: `data.chatMessages.filter(m => m.archived !== 1).slice(-4)`.
   - Profile “Past Conversations” Card: count active/archived directly from `data.chatMessages`.
   - ChatHistoryDrawer: sort all `data.chatMessages` by createdAt descending and visually mark archived records.
   - Backup `exportAllData`: `db.chatMessages.toArray()` remains unchanged, including all archives, satisfying PRD acceptance criterion 2.

5. **New UI**
   - `{{APP_REPO_DIR}}/src/features/profile/ChatHistoryDrawer.jsx`: full-screen slide-up drawer.
   - Add an inline Card to Profile.jsx: title “Past Conversations,” subtitle “N messages · X archived,” button “Browse.”
   - Visual specification: mark archived messages “· Past,” opacity 0.65, text-xs (11px), inkSoft color (`#3a3128`).

## Consequences

### Benefits
- **Complete data**: all chat history remains; backup JSON includes every archived record.
- **Home performance**: recorded Home rendering complexity improves from `O(N)` to `O(min(N,30))`, especially for large N.
- **User capability**: direct history browsing expands the original PRD and reuses the Drawer visual pattern.
- **Schema readiness**: archived has a secondary index, ready for frequent `where('archived').equals(0)` queries if needed.
- **Existing data safety**: upgrade() explicitly marks old messages archived=0 for consistent query semantics.

### Costs
- **Dexie v1 becomes v2**: the next schema change requires v3; do not go backward.
- **1 React component and 1 Card entry**: Profile.jsx grows by ~30 lines, remaining <5KB.
- **1 extra database read per message**, possibly 1 write: recorded as <5ms in IndexedDB, negligible.
- **Archive counts can lag**: actions in another tab while the drawer is open do not synchronize counts immediately; considered rare and acceptable.

### Reconsideration
- **Reversal**:
  1. Remove ChatHistoryDrawer and the Profile Card; users lose the entry point, but data remains.
  2. Remove the Home.jsx archived filter; Home can show all history again.
  3. Keep the archived field for forward compatibility.
- **Estimated reversal cost**: within 1h; remove ~80 lines, 1 component, and 1 Card entry.
- **No data loss**: archived=1 records remain intact and behave as ordinary active messages after reversal.

## Notes

- Archive after add, not before; add failures do not interfere with the archive logic.
- Use numeric `0`/`1` for `archived`, not boolean `false`/`true`, because IndexedDB does not index booleans.
- Future weekly/monthly or 7-day inactivity archiving can add parallel rules alongside addChatMessage.
