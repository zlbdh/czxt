## Context

After PROP-001 through PROP-004, the workflow rules were fairly complete: agent/'s 5 groups, DoD, and project health checks. zlbdh asked whether completing an APK and smoke test would be remembered and reflected automatically. The answer was **no**.

The rules were **semiautomatic**: AI needed the user to report facts, then had to run commands and update documentation. Review found 12 actual problems:

1. APK and smoke completion did not automatically update Sprint status.
2. Cowork ↔ Claude Code sessions did not synchronize.
3. A new session did not know the previous state.
4. Files nearing size limits generated no proactive warning.
5. Nobody maintained the RETRO trigger counter.
6. F-XXX status transitions from ⏳ to ✅ lacked clear conditions.
7. F-XXX numbering was inconsistent.
8. DoD did not distinguish actions supported by each environment.
9. Placeholder files lacked completion triggers.
10. Context degraded during long sessions.
11. The ADR README index and document status fields formed two sources.
12. Number lookups did not run proactively.

## Decision

Upgrade to **90% fully automatic** through 13 actions in 4 phases:

### P1 — State Inference Skill (Core)
Create [`agent/skills/状态推断.md`](../../../agent/skills/状态推断.md) with 5 inferences: APK completion, code changes, RETRO triggers, ADR consistency, and cross-session state. AI **proactively** compares documents with actual state, moving from waiting for the user to asking whether an observed transition should be applied.

### P2 — Cross-Session Cache
Create root [`状态.md`](../../../状态.md) as a cross-session cache. **Overwrite its top section at every session end** and read it at every session start. Explicitly state that it is a cache, not truth, to prevent competing sources.

### P3 — Complete Rules
- Add a DoD capability matrix for Cowork / Windows / Claude Code.
- Create [`agent/rules/F编号规则.md`](../../../agent/rules/F编号规则.md) for namespaces.
- Add completion triggers to the git / security / mcp placeholders.
- Reconcile ADR index and header status through inference 4.

### P4 — Verify
Run 4 scenarios: F-001 APK completion, session switch, RETRO trigger, and health check v17.

## Consequences

### Benefits
- ✅ Proactive reconciliation reduces user effort by the recorded 70% target.
- ✅ Cross-session synchronization moves from 0 to two defenses: 状态.md and the synchronization package.
- ✅ Framework coverage moves from v15's 14 passing dimensions to v18's closure of 12 problems plus 14 passing dimensions.
- ✅ Long-session degradation receives formal handling through startup and mid-session checks.
- ✅ Environment-specific DoD avoids claiming unsupported actions were executed.

### Costs
- ❌ 3 new files: state inference, numbering rules, and 状态.md, increasing maintenance locations.
- ❌ More DoD items, mitigated by referencing skills instead of embedding their contents.
- ❌ 状态.md risks becoming another competing source, mitigated by its explicit cache status and preferring Read over Bash.

### Mitigated Risks
- Mount cache delays: both state inference and health-check skills require Read rather than reliance on Bash.
- Drift between 状态.md and Sprint requirements: Sprint requirements are truth; 状态.md is a cache.
- DoD growth: split into core items and referenced extensions.
