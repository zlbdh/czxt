## Context

After ADR-009 (PROP-006), zlbdh asked during health check v22 whether the framework still had problems. Review identified 14 potential risks:
- 4 actual near-term risks.
- 5 monitoring-level risks already listed in RETRO-003.
- 3 nonurgent long-term evolution issues.
- 2 meta-level issues that cannot be fully resolved.

zlbdh requested resolving all of them. This ADR closes the **9 addressable risks**: 4 actual + 5 monitoring. **The other 5 are accepted as they stand.**

## Decision

### P1 — 4 Actual Risks

#### P1-1: Concurrent Writes to 状态.md
**Problem**: Cowork and Claude Code both modify 状态.md; the later write overwrites the earlier one.
**Resolution**: add a write convention. Read and check mtime before writing; if it differs from the last read, merge instead of overwriting. zlbdh arbitrates conflicts.

#### P1-2: F-001 Depends on User Reporting
**Problem**: completing APK and smoke without telling AI leaves status stale.
**Resolution**: strengthen inference 1 to run **on every AI response**, not only session startup. If status is ⏳ awaiting APK and the latest APK is newer than code completion, ask proactively. A dismissal starts a 7-day cooldown.

#### P1-3: 8 Files Near 7KB Have No Proactive Split Trigger
**Problem**: after PROP-001, files grew back to 6000–6741B; 8 approached 7KB without a trigger.
**Resolution**:
- Add a 6500B mandatory-split threshold to health-check dimension 1.
- Add a hard rule to agent/rules/写代码.md: at ≥6500B, immediately open a splitting PROP rather than waiting for expansion.

Prevent the endless split → regrow → split cycle.

#### P1-4: No Recovery Procedure for AI Deletions
**Problem**: the sandbox is not directly connected to Git; accidental deletion has no standard procedure.
**Resolution**: add accidental-deletion recovery to agent/rules/安全与隐私.md: stop immediately, tell zlbdh, do not reconstruct from memory, and prefer git restore.

### P2 — 5 Monitoring Risks from RETRO-003

#### P2-1: Refine Inference 3's Threshold Algorithm
**Problem**: `3 × (retro_count + 1)` fails when a RETRO is early or late.
**Resolution**: use **incremental counting**: total_l3 minus the count covered by the previous RETRO ≥3.

#### P2-2: Allow a 3 ± 1 RETRO Window
**Problem**: exactly 3 changes is too rigid.
**Resolution**: allow 3 ± 1. A RETRO may happen after 2 dense architectural changes or after 4 simple changes. zlbdh decides.

#### P2-3: Warn on PROP Cards in Progress for >7 Days
**Problem**: ongoing proposals can be forgotten without a time limit.
**Resolution**: add inference 6. When mtime is older than 7 days, report the number of stalled days and ask whether to abandon or split the proposal.

#### P2-4: Monitor Placeholders Proactively
**Problem**: git/security/mcp completion triggers require evaluation, but no mechanism performs it.
**Resolution**: add inference 7. During implementation, scan changes for relevant keywords and prompt proactively.

#### P2-5: Clean Up the 状态.md Decision Table
**Problem**: the table grows indefinitely.
**Resolution**: automatically move entries older than 7 days into the historical archive section. Dismissed suggestions may be raised again after the 7-day cooldown.

## 5 Accepted Issues

- #10 Multiple contributors: unnecessary for a personal app.
- #11 Project migration: revisit if Cowork becomes unavailable.
- #12 Complete backup: Git provides fallback.
- #13 The health-check skill's self-reference paradox: philosophical, requiring human review.
- #14 Cognitive burden: a design choice, not a bug.

## Consequences

### Benefits
- ✅ All 4 actual risks are recorded as closed, preventing near-term occurrence.
- ✅ All 5 monitoring risks become built-in state-inference or health-check rules.
- ✅ Recurring large-file growth gets its first hard 6500B threshold.
- ✅ Concurrent sessions and accidental deletion receive standard procedures.

### Costs
- ❌ State-inference skill grows with inferences 6/7 and refined algorithms.
- ❌ 状态.md gains write-convention and cleanup sections.
- ❌ More detailed rules slightly increase AI memory burden.

### Mitigated Risks
- ✅ State-inference growth remains controlled, <1KB.
- ✅ The 6500B rule conflicts with 8 existing warning-level files: **do not split them immediately**; trigger splitting when each is next expanded.

## Position

ADR-010 **does not claim complete perfection**:
- **5 issues remain accepted**: collaboration, migration, backup, self-reference, and cognitive load. They are design tradeoffs.
- **3% remains manual**: AI is reactive, not a daemon; 100% automation is not achievable.
- **Do not immediately split the 8 existing files under the 6500B rule**; wait for expansion to trigger it.

Recognizing limitations is part of mature engineering.

## Summary of the Recorded Decision

ADR-010 moves from 95% automation and 14 potential risks to 97%, no actual risks, and 5 accepted issues: a sustainable steady state for the framework.
