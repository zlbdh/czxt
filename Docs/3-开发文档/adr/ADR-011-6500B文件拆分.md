## Context

ADR-010 P1-3 established a hard rule: **split source files ≥6500B without waiting for expansion**. It also stated that the existing 8 files should not be split immediately, but when expansion triggered it.

During PROP-006/007 implementation, 6 files crossed 6500B:

| File | Bytes | Reason |
|---|---|---|
| `agent/skills/状态推断.md` | 9715B | Created by PROP-005, repeatedly expanded by PROP-006/007: inferences 5–7 and algorithm refinement |
| `agent/workflows/实施循环.md` | 9309B | Repeated additions: 5 core DoD checks, synchronization package, capability matrix |
| `agent/skills/项目体检.md` | 8078B | PROP-006/007 added the 6500B threshold and cross-session dimension after PROP-005 |
| `{{APP_REPO_DIR}}/src/shared/DayDrawer.jsx` | 6741B | PROP-002 added ChatMessageRow and extensive grouped rendering |
| `agent/rules/改动分级.md` | 6694B | PROP-005/006 added PROP status conventions and L1/L2 details |
| `{{APP_REPO_DIR}}/src/features/timeline/Timeline.jsx` | 6564B | PROP-003 combined calendar placeholder, entry interaction, and summary rendering |

F-001's closure health check exposed these violations of the hard threshold; splitting was required.

## Decision

Keep core responsibilities in the main file and extract helpers. **Preserve functionality, routes, and data structures.**

### Documentation: 4 Files

| Main file retains | Extracted files | Division |
|---|---|---|
| `状态推断.md`: entry and 7-item index | `状态推断-推断项.md` + `状态推断-跨session监控.md` | Inferences 1–4 in the first; 5–7 in cross-session monitoring |
| `实施循环.md`: workflow backbone | `实施循环-DoD.md` | Complete L1–L4 DoD and synchronization package |
| `项目体检.md`: entry, execution, report template | `项目体检-检查项.md` | Full logic, commands, and assessment templates for 5 checks |
| `改动分级.md`: L1–L4 classification | `改动分级-状态字段.md` | PROP status conventions and state machine |

### Code: 2 Files

| Main file retains | Extracted files | Division |
|---|---|---|
| `DayDrawer.jsx`: drawer shell, close, composition | `DayDrawerBody.jsx` + `DayDrawerRows.jsx` | Body groups sleep/meals/etc.; Rows renders individual text/chat rows |
| `Timeline.jsx`: state, data flow, shell | `TimelineCapture.jsx` + `TimelineSummary.jsx` + `TimelineCalendar.jsx` | Entry capture, daily summary, calendar placeholder |

**Note**: PROP-008 proposed `DayDrawerGroups.jsx`; implementation used `DayDrawerBody.jsx`, matching its responsibility for the whole body rather than grouping alone.

## Consequences

### Benefits
- ✅ All 6 scoped files return below 6500B.
- ✅ Main-file responsibilities are clearer: DayDrawer is a shell, Timeline a state container.
- ✅ Helpers can evolve independently within their boundaries.
- ✅ ADR-010 P1-3 is first applied through proactive splitting instead of warnings alone.

### Costs
- ❌ Agent documentation increases from 4 to 8 files, but smaller indexes improve navigation.
- ❌ Timeline's import chain grows slightly; routes and data flow remain unchanged.
- ❌ Historical PROP/ADR references, such as inference 5 in 状态推断.md, remain unchanged under ADR-007 §C; redirect notices aid navigation.

### Risks: Mitigated and Newly Found
- ✅ Extracted code passed four layers: `wc -lc`, esbuild, vitest, and Vite build.
- ✅ Main Markdown files link back to extracted files.
- 🔴 **DoD exceeded the threshold after PROP-009**: `实施循环-DoD.md` was ~5KB after extraction, then grew to 7029B with the 6-section handoff. This is a **new violation after PROP-008**, outside its scope. Recommend PROP-010 to extract the handoff into `交接卡格式.md`.
- 🟡 **`项目体检-检查项.md` is 6200B**: run `wc -c` before its next expansion and extract the 6500B threshold history section if needed.
