## Context

PROP-009 / ADR-012 upgraded synchronization to a 6-section handoff and embedded it in `agent/workflows/实施循环-DoD.md`. The complete template grew the file to **7029B**, above ADR-010 P1-3's mandatory-split threshold of ≥6500B.

Claude Code found the violation during PROP-008 closure, recorded it in handoff warning section ⑤, and recommended PROP-010.

The rule was violated immediately after its introduction. **Its detection also showed that the rule worked**: the trigger produced a response.

## Decision

Extract the complete handoff template from `实施循环-DoD.md` to `agent/workflows/交接卡格式.md`.

Replace it in `实施循环-DoD.md` with:
- A short reminder of the two defenses.
- A reference to the complete template in `交接卡格式.md`.

## Implementation

| File | Change | Bytes |
|---|---|---|
| `agent/workflows/交接卡格式.md` | Create | 0 → 3409B |
| `agent/workflows/实施循环-DoD.md` | Extract handoff; keep short reference | 7029B → ~5800B |

After implementation, files ≥6500B = 0 ✅.

## Consequences

### Benefits
- ✅ 实施循环-DoD.md returns to the safe range.
- ✅ Handoff formatting evolves independently without expanding DoD.
- ✅ The PROP-009 side effect was caught by **three defenses**: ADR-010 P1-3, Claude Code's health check, and handoff section ⑤.

### Lessons
- **The first implementation after introducing a rule should check itself for violations.**
- DoD health checks and state inference must **include files introduced by the current implementation**.

### Unavoidable Effects
- Any new mechanism, including a 6-section handoff, adds bytes when written down.
- The key is fast detection and response; this correction took <1 day ✓.
