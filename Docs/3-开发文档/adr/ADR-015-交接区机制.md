## Context

PROP-009 / ADR-012 introduced 6-section cards at the top of `状态.md`, upgrading PROP-006's 3-section package. Practice exposed problems:

| Problem | Severity |
|---|---|
| Only 1 card can be stored; overwriting the top loses history | 🔴 |
| Concurrent sessions modifying 状态.md can conflict | 🟡 |
| 状态.md mixes truth and cache responsibilities | 🟡 |
| Recipients can only read the latest card; overwritten cards are lost | 🔴 |

On 2026-05-11, zlbdh proposed a **handoff area**: a separate file per card and three state directories for pending, received, and historical cards.

## Decision

Create top-level `交接区/`, replacing overwrite-in-place cards in 状态.md with an event stream of independent files.

### Directory Structure
```
交接区/
├── README.md
├── 待接手/                ← Write here after implementation
├── 已接手/                ← Recipient moves here after completing work; permanent record
└── 历史归档/              ← Archive after 30 days, grouped by month
```

### Filenames
`YYYY-MM-DD-HHMM-任务-从角色到角色.md`

Example: `2026-05-11-1435-F-006-Codex到zlbdh.md`.

### Move Responsibility
**After completing implementation, the recipient moves the card they accepted** from `待接手/` to `已接手/`, while writing a new card to `待接手/`.
When zlbdh confirms, AI moves the card addressed to zlbdh into `已接手/`.

### Changed Role of 状态.md
- Before, PROP-009: complete latest 6-section handoff at the top.
- After, PROP-011: concise latest-card summary and link to the newest pending card.
- Details live in independent 交接区/ files.
- 状态.md returns to snapshots, progress reference, and inference decisions.

## Final Three-Layer Structure

```
交接区/待接手/2026-XX-XX-HHMM-任务-从到.md  ← Complete 6-section file: event stream
        ↓ Link
状态.md top summary                         ← Minimal snapshot
        ↓ Copy
Compact handoff text                        ← User pastes into another session
```

## Quantitative Benefits

| Measure | PROP-009 | PROP-011 |
|---|---|---|
| Historical traceability | ❌ Overwritten | ✅ Separate file per card |
| Concurrent-session conflicts | ⚠️ Shared writes conflict | ✅ Separate files |
| Which card to read | Latest only; old lost | ✅ Select by time or task |
| 状态.md responsibility | Truth and cache mixed | Snapshot only |
| Handoff time | ≤1 min, already improved | ≤30s, clearer selection |

## Supersession

ADR-015 **does not supersede ADR-012**; it upgrades **storage location**:
- Keep ADR-012's 6-section format.
- Move storage from the top of 状态.md to independent 交接区/ files.
- Keep the top of 状态.md as summary plus link.

## Consequences

### Benefits
- ✅ History is traceable through git log and filename timestamps.
- ✅ Separate files reduce session conflicts.
- ✅ 状态.md has one responsibility.
- ✅ Recipients know which card to read.

### Costs
- ❌ One more top-level directory adds cognitive load.
- ❌ Move responsibility must be explicit; recorded in 交接区/README.md.
- ❌ Existing sessions must adapt from reading only the top of 状态.md.

### Mitigated Risks
- ✅ The recipient moves their accepted card after completing work.
- ✅ Inference 5 warns when the card count is ≥3.
- ✅ Received and historical cards are retained permanently, never deleted.
