## Context

PROP-007 / ADR-010 P1-3 required splitting every file ≥6500B; PROP-008 / ADR-011 split 6 violations. RETRO-005 then exposed **a mismatch between the rule and tool capabilities**.

### Trigger Evidence from RETRO-005

| # | Signal | Severity |

| 2 | Cowork-specific limits were applied to Claude Code / Codex despite their lack of mount write limits | 🔴 Card 3 |
| 3 | Repeated unnecessary component extraction to accommodate Cowork violated YAGNI | 🟡 |
| 4 | The PM was misled too: F-LAYOUT-2 nearly prompted Claude Code to extract HealthExercises | 🟡 |
| 5 | Inconsistent with ADR-016's tool-specific governance pattern | 🟡 |

### Meta-Level Insight: RETRO-005 Insight 1

PROP-011 / PROP-012 / PROP-013 share a pattern:
**A single-tool or single-dimension constraint is incorrectly generalized to multiple tools, creating noise; separate it at the appropriate level.**

## Decision

Replace the universal mandatory 6500B split rule with **tool-specific guidance**.

### Thresholds

**Cowork: mount truncation risk, hard truncation at 9KB**

| Size | Status | Action |
|---|---|---|
| <6000B | ✅ Safe | Edit / Write allowed |
| 6000–6500B | 🟡 Warning | Verify with Read before Edit; prefer Python/Bash for larger writes |
| 6500–8000B | 🟡 Advisory | **Must bypass Edit with Python/Bash**; no mandatory splitting PROP |
| ≥8000B | 🔴 Danger, near 9KB truncation | Do not use Cowork Edit; hand off to Claude Code / Codex |

**Claude Code / Codex: local filesystem, no mount**

| Size | Status | Action |
|---|---|---|
| <8KB | ✅ Safe | No restriction |
| ≥8KB | 🟡 Consider extracting components | Single-responsibility engineering advice; **does not block implementation** |

### Read Verification Required for Decisions Based on Bash `wc -c`

RETRO-005 card 2: Bash reads through a mount **may return stale cache**.

For decisions such as component extraction or warning actions, **verify actual size with Read**:
- If Bash and Read differ, trust Read; Bash may reflect mount cache.
- This requirement is recorded in the dimension 1 command template in `agent/skills/项目体检-检查项.md`.

### Engineering Guidance Retained

For every tool, files **>8KB carry an advisory to extract responsibilities**. This is engineering quality guidance independent of tool capability.

## Consequences

### Benefits
- ✅ Read verification addresses recurring false mount-cache warnings.
- ✅ Claude Code / Codex avoid artificial write limits; the recorded benefit describes <8KB guidance as advisory.
- ✅ Cowork retains mount safety margins and the 6500B Python/Bash alternative.
- ✅ Matches ADR-016's tool-specific governance pattern.
- ✅ Retains the 8KB single-responsibility guidance.

### Costs
- ❌ Two threshold tables increase cognitive load.
- ❌ Weaker health warnings require two-source verification and tool context.

### Mitigated Risks
- ✅ Claude Code / Codex producing 7–8KB files: the 8KB extraction advisory provides a backstop.
- ✅ Cowork Edit truncating >6500B files: thresholds, warnings, and Python/Bash alternatives.
- ✅ Repeated Bash cache problems: mandatory Read verification in command templates.

### Preserved
- ✅ ADR-010 P1-3's historical rationale for 6500B.
- ✅ ADR-011 / PROP-008 historical splits; single responsibility remains useful.
- ✅ Cowork **still bypasses Edit for >6500B files**; Python/Bash addresses a physical constraint.
