## Context

After Sprint-3 closed and PROP-016 cleared architecture debt, a meta-insight emerged: the framework itself (`agent/` + `Docs/` + `确认改动/`) should be managed like application code, with a version history, health checks, and a quick-start guide.

The {{PROJECT_NAME}} framework lacked three supporting mechanisms:

1. **Quick onboarding for a new tool**: `agent/INDEX.md` is a technical reference covering five semantic groups, but lacks a five-second entry point. A new AI tool must scan the entire agent/ tree (~15 minutes) before it can work.

2. **Automated health monitoring across sessions**: The current process relies on zlbdh explicitly asking, "@Mimi, run a project health check." AI judgments made through the mount cache can fail at decision points (RETRO-005 card 2 / PM self-corrections #9/#12: bash `wc -c` through the Cowork mount returned stale cached data and produced false size warnings).

3. **A lightweight change log**: Small framework changes, such as naming fixes, reference fixes, and comment improvements, have no suitable record. A PROP is too heavy; leaving no record loses traceability.

Two other projects owned by zlbdh, account management and srm server management, already had mature versions of these mechanisms. PROP-017 chose **reverse learning**: adopt the sibling projects' mechanisms and adapt them to {{PROJECT_NAME}}.

## Decision

Introduce three framework meta-rule mechanisms **together; they must not be introduced independently**:

### 1. Root `AGENTS.md` (five-second entry point)

Create `{{PROJECT_ROOT}}\AGENTS.md` (90 lines / 3488B), covering five startup steps, the mandatory sensitive-operation checklist (Class C boundaries), file-size rules (PROP-013 / ADR-017), cross-tool collaboration (concise chat steps ①-⑥, PROP-014 / ADR-018), and the three-level process-first decision rule (🔴 / 🟡 / 🟢).

**Hard rule**: Keep the entry point minimal. Detailed rules always live within `agent/`; this file only directs the reader. Before editing, ask whether a new tool can still read it in five seconds.

### 2. `tools/check-operating-system.ps1` (automated health checks; historical entry point)

Create a PowerShell 5.1+ compatible script (~290 lines). It originally implemented four phases and has since moved and expanded:

| Phase | Checks |
|---|---|
| P4a | Basic integrity: 61 required items, including AGENTS.md / agent/CHANGELOG.md / 项目体检-检查项-7-8.md |
| P4b | Byte size: tool-specific tiers, expanded file inventory, and color indicators |
| P4c | agent/ reference frequency: ≥10 high / 5-9 medium / 2-4 low / 1 very low / 0 dead code |
| P4d | 状态.md freshness within 30 days: both mtime and content date stamps |

Current usage: `powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-operating-system.ps1`.

### 3. `agent/CHANGELOG.md` (fourth record collection; historical entry point)

The current source of truth for the lightweight change log is `操作系统/00_变更记录/CHANGELOG.md`. This record preserves the naming context of `agent/CHANGELOG.md` at the time.

| Change type | Primary record |
|---|---|
| L3+ architecture / meta-rule evolution | PROP + ADR + CHANGELOG (index entry only) |
| Sprint retrospective | RETRO + CHANGELOG (index entry only) |
| **L1-L2 incidental work / dead-code removal / naming fixes** | **CHANGELOG as the primary record** |
| Reverse learning adopted from another project | CHANGELOG as the primary record, plus a PROP if the impact is substantial |

Format rule: four lines per entry (what changed / trigger / acceptance result / downstream impact), with a maximum of 10 lines.

## Key tradeoffs

### 1. PS1 is authoritative; documentation explains it

P4c / P4d logic also appears in `agent/skills/项目体检-检查项-7-8.md` (dimensions 7+8) and `agent/skills/状态推断.md` (inference 10). For future logic changes:

- Change PS1 → update documentation in the same PROP process.
- Change documentation without PS1 → the next PS1 run exposes the inconsistency.

The tool is the source; documentation is its explanation.

### 2. AGENTS.md is the sole root-level exception for an AI entry file

Under ADR-007 / AI边界.md Class C, AI cannot modify root `_framework`-level files. AGENTS.md is special: **it is the entry point for AI**, so AI is well suited to write it.

AGENTS.md changes are therefore **Class B**: zlbdh review is required, but the PROP/ADR process is not, as with README.md.

### 3. CHANGELOG grows monotonically; monitor it through RETRO topics

CHANGELOG is **append-only** by design and continues to grow with the project. It was 4453B before PROP-017 closeout and reached 6821B (the advisory range) after the P3/P4/P5 entries.

This ADR does not solve that issue. Add "Archiving old CHANGELOG entries" to RETRO-008: archive cold entries by Sprint / half-year into `agent/CHANGELOG-2026H1.md`.

### 4. PS1 depends on Windows; mirror its logic in bash as a fallback

`pwsh -File` requires PowerShell 7+, while zlbdh uses PS5.1 (`powershell -File` is the recommended fallback). Codex runs on remote Linux and **cannot run PS1**.

Inference 10 / 项目体检-检查项-7-8.md therefore provide mirrored bash logic with the same thresholds and dimensions for cross-tool consistency.

**When to run the bash mirror** (added in PM self-review #14):
- **Mandatory at session start**: Codex / Cowork startup automatically runs the P4d bash mirror through inference 10 in `agent/skills/状态推断.md` to check 状态.md freshness.
- **Proactively after major changes**: After framework restructuring, major agent-file edits, or reference-chain changes, AI runs the P4c bash mirror for reference frequency.
- **Prefer an actual PS1 run**: When PS1 is available, such as on zlbdh's Windows machine, its output is authoritative. Use the bash mirror only when PS1 is unavailable.

## Consequences

### Benefits

- **Faster tool onboarding**: A new AI session starts in five seconds by reading AGENTS.md, without scanning the entire agent/ tree.
- **Observable health**: One PS1 command produces objective results without relying on AI judgment or the bash cache.
- **Traceable small changes**: CHANGELOG handles L1-L2 work without a heavyweight PROP.
- **Avoids mount-cache traps**: PS1 runs directly on the Windows host, bypassing the mount and providing trustworthy ground truth at decision points.
- **Mature bidirectional learning**: {{PROJECT_NAME}} mechanisms can later flow back to sibling projects, supporting two-way iteration.

### Costs

- **Redundant maintenance across three areas**: AGENTS.md / PS1 / CHANGELOG / agent/skills/ all describe checks and interpretation and must stay aligned. This ADR makes PS1 authoritative.
- **File-size effects**: After PROP-017 P5, `agent/skills/项目体检.md` was 6177B (warning) and `agent/CHANGELOG.md` was 6821B (advisory). These were expected and entered RETRO tracking.
- **PS1 portability**: Remote Codex has no Windows shell and cannot run PS1, so it relies on mirrored bash logic.

### Risks and mitigations

- **PS1 / documentation drift**: A one-sided logic change will be exposed by the next health check. Mitigation: this ADR defines the authority; documentation PRs must include PS1 review.
- **Uncontrolled CHANGELOG growth**: It could exceed 50KB within five years. Mitigation: plan the archiving strategy through RETRO-008.
- **AGENTS.md drift**: Major agent/ changes without a matching AGENTS.md update leave new tools with an inaccurate entry point. Mitigation: AGENTS.md is the first required P4a item.
- **Mount-cache effects on PS1 edits themselves** (PM self-review #14): PS1 provides ground truth, but editing it still uses Cowork Edit/Write and can hit mount-sync traps (three incidents in PM self-corrections #9/#12). Mitigation: after significant PS1 changes, an actual Windows run is mandatory, as established during PROP-017. bash stat is not trustworthy.
