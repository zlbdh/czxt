# ADR-039 · 统一借鉴区与闭环治理

- **状态**：现行
- **日期**：2026-07-18（2026-07-19 完成实施验收；2026-07-22 完成终审加固）
- **决策责任**：项目 PM 编排；操作系统 PM 起草与实施；测试相关 PM 验收
- **关联**：[PROP-004](../../../确认改动/已审批/已完成/PROP-004-2026-07-18-完整借鉴闭环.md) · [设计规格](../2026-07-18-借鉴闭环-设计规格.md) · [设计规格附录](../2026-07-18-借鉴闭环-设计规格-附录.md)

> 本 ADR 已通过实现、临时实例 dogfood、模板与 generic project 双端 P4a-P4t 新鲜验收，现作为统一借鉴闭环的当前决策边界。

## 背景

ADR-021 引入了从姐妹项目反向学习的机制，但其历史方案以入口、体检和轻量日志为主，没有统一保存“从哪里学、冻结的是哪个版本、为什么采纳或拒绝、落到哪里、如何验证”的可执行合同。若只靠临时对话或外部路径，来源会漂移、决策与实施会混写，模板还可能夹带具体项目事实或形成业务运行时依赖。

本次需要在不新增 PM 角色、不改变既有路径白名单、不执行来源内容的前提下，把借鉴变成模板可实例化、实例可审计、检查器可离线验证的闭环。同时，当前模板的 Windows PowerShell 5.1 兼容性和模板/实例识别必须先成为可靠底座。

## 决定

1. **统一单根。** 所有借鉴元数据统一位于根级 `借鉴区/`。模板只带 README、卡片模板、忽略规则和空目录骨架，不维护第二份活跃来源索引；实例中的来源卡和事项卡分别是来源事实与事项事实的单一真源。

2. **来源 capture 不可变。** 借鉴事项固定绑定 `source_id + capture_id + fingerprint`。正式 capture 一旦就绪，其身份与指纹字段不可改写；刷新不得改写旧 capture：完整 fingerprint 不变且与唯一合法 ready 的稳定事实一致时返回 REUSED，fingerprint 改变时新增 capture，旧事项保持原绑定且不得自动跟随。退役只追加管理历史，并先证明没有活动事项引用。

3. **事项状态与决策分离。** `lifecycle_status` 表示流程进度，`decision` 独立表示 `pending / adopt / adapt / reject / defer`。每次状态变化追加历史；关闭条件按决策分支验证。`adopt / adapt` 的目标必须是真实安全常规文件；fresh bullet 使用 `time / command / exit / evidence` 机器格式且不得早于最近一次进入 `verifying`，其 evidence 必须是精确 `borrowing-evidence/v1`，绑定 bullet 字段与全部目标文件清单摘要，任意非空文件或 staging 成员不能冒充证据。已关闭事项用 seal 检测意外或不合规改写，但不宣称抵抗能同时重算 seal 的恶意写者。

4. **显式根模式与不覆盖实例化。** 模板根使用 `.czxt-template-root`，实例根使用 `.czxt-project-root`；二者同时存在或均不存在均为硬失败。实例化不复制模板标记，只生成实例标记，并只复制借鉴空骨架，不覆盖实例已有来源、事项或本地缓存。`AppRepoDir` 与每个复制/建目录/直接写目标都必须在计划期和紧邻落盘点证明位于项目根内且祖先无 reparse；文件更新采用 no-overwrite 的 `target→backup`、`prepared→target` 两段移动。项目根以及源与目标通过 handle 和 `GetFinalPathNameByHandleW` 绑定物理最终路径，拒绝 `subst` 等物理别名重叠；每个已安装或改写输出即时登记到输出 manifest，最终 marker/成功输出前保持全部条目的只读共享 lease。`状态.md` 是必备事务输出：`-Force` 先绑定并保留既有五元组、跳过模板覆盖，再无条件按 manifest ExpectedState 做 CAS 追加；快照后缺失或被替换为目录必须硬失败，不得生成 marker 或成功输出。`-Force` 对既有目录逐文件原位合并，禁止产生嵌套副本。实例化是逐文件事务集合，失败不承诺全局原子回滚，所有权不明时保留可审计残留而不覆盖或猜测删除。

5. **Gate 0 先行。** 纳入正式范围的 PowerShell 脚本必须满足 Windows PowerShell 5.1 可解析和 UTF-8 BOM 合同；模式契约、实例化后的 BOM 保留及失败退出码传播必须先于核心能力和 P4t 验收。

6. **P4t 只读且离线。** P4t 仅检查模式、骨架、卡片 schema、引用、状态转换、关闭条件、路径安全、缓存一致性和业务零依赖，退出码区分通过、警告和硬失败。每个公开 leaf 从安全 marker 独立判定实际 RootMode 并拒绝伪造 Mode；业务文本按可严格解码内容而不是有限扩展名识别，根相对 `借鉴区/` 按 path token 边界拦截，超限疑似文本 fail closed，二进制不执行；`dist / build / .next / target / out` 等可部署构建或运行产物不得整体跳过。隔离扫描对不超过 8 MiB 的文件三轮全量读取，对更大文件三轮只绑定 identity、length 与前 64 KiB，并明确不保证观测范围外的尾部同身份同长度改写；三轮实际读取共用一次全调用共享预算：最多 `20000` 个文件、`100000` 个目录项、`512 MiB` 摘要读取，项目卡单次 `1 MiB`、首尾两次合计 `2 MiB`。P4t 不联网、不刷新来源、不执行、构建或安装外部内容，也不修复或写回卡片。

7. **唯一用户入口与受测机器层。** 面向操作者的唯一入口是 `能力资产/skills/借鉴.md`，覆盖接入、评估、落地和审计。Skill 调用受契约测试的捕获 façade/helper 完成 Git、本地或网页来源冻结；机器层不形成第二套用户流程，不暴露来源执行能力。

8. **模板中立、业务零直接依赖。** 模板不得携带任何具体来源源码、具体来源卡或事项卡。业务代码、依赖配置、构建脚本和运行时读取不得直接消费 `借鉴区/` 或来源缓存；获准内容必须复制或适配到既有目标路径，再按该路径责任边界验证。文档中的来源链接和审计标识不等于运行时依赖。

9. **验收边界固定。** 完成证据依次来自 Gate 0、核心契约、P4t 正反例、临时实例 dogfood、P4s/P4t 专项与 P4a-P4t 总体检。所有这些验收均不联网、不执行来源内容；未获得另行授权时也不执行 commit、push、tag、release、发布或外部分发。

10. **关闭与元数据必须 fail closed。** 正式关闭只调用 `close-borrowing-item.ps1`：从活动卡生成候选、以 no-overwrite 事务安装、调用 seal、运行完整根 P4t；P4t exit 0 后仍须锁住正式卡复核 identity 与 sealed 字节，锁内清理 staging 才返回成功。只有 ownership 可证明且未进入 `content-deleted` 的失败允许恢复原活动卡；材料已绑定当前正式对象而仅 `borrow_id` 不一致时仍可按完整快照安全恢复。其他 `seal-ownership-unproven` 必须保留当前正式卡与 staging，`content-deleted` 不可逆完成点后不回滚正式卡。staging 所有权链固定：通过受信父目录句柄相对原子创建 staging 目录；首个 `原活动卡.bin` 以目录句柄相对 CreateNew，并在同一 handle 写入、flush 并绑定，文件 lease 贯穿整个事务以让目录保持非空；候选 `借鉴卡.md` 也以目录句柄相对 CreateNew。清理顺序固定为 `Candidate→retained Original→content-deleted→directory`：Candidate 以单次打开的绑定 handle 完成验证并在同一 handle 设置 delete-pending；retained Original 通过保留 lease 在同一 handle 设置 delete-pending；随后立即进入 `content-deleted`，最后由目录创建句柄同句柄删除。验证与路径打开之间不得留窗口；创建失败只删除本事务句柄绑定对象。P4t exit 0 后，正式卡终锁必须单次 OPEN_REPARSE_POINT 打开，并从同一 handle 复核 canonical path、常规非 reparse 类型、link count=1、identity、length 与 bytes；该排他 lease 持有到 staging 清理结束。禁止“先安全路径验证再按路径重开”。seal 后 staging 候选更新遵循双状态合同：正式卡所有权快照与当前 staging 候选快照是两个独立状态，回滚必须分别验证；不得提前把 staging 期望改成 sealed 字节。`Set-BctCandidateBytes` 的 Set 提交后状态对象先更新，再执行后续可失败复核，确保异常分支看到实际已提交候选。并发改写不得被覆盖。所有将进入 tracked 来源卡的标识、locator、授权说明与 facts/响应元数据在规范化入口和最终 renderer 复用同一凭据检测；capture 根与快照直接成员按来源类型精确枚举，未知成员一律冲突。

## 2026-08-24 入库前安全补充

- 捕获事务把 staging、正式 capture、既有 capture 与 P4t 组件分别绑定到持续句柄；staging 原子移动后必须按 move 前账本逐成员复核 root/member identity、length 与 SHA-256，repair 的快照和状态文件两段移动之间重新封印。
- 树 seal 不再把文件全文常驻内存：同一文件句柄以 1 MiB 缓冲流式计算 SHA-256，只保留 32 字节摘要；显式 DFS 每发现一项就计数，固定上限为 `20000` 个成员和 `536870912` 总字节，越界立即 `resource-limit`。
- cleanup 只消费 ownership ledger 中的绑定对象；初次 Git runner 与 post-move auxiliary 同样走精确账本。晚到普通文件、同字节新 identity 或原生 ADS 均失败关闭并保留未知对象；native rename 已提交后的异常从同一 handle 刷新真值后再决定回滚。
- HealthyReuse 与 RepairMissingCache 在 cleanup 后追加最终绑定检查，把事务线性化点放到最后一个内部动作之后。该合同不承诺函数返回后外部进程永不改写目录；晚到 unknown 虽会保留，但已登记成员可能已部分进入删除状态，因此不得描述为全树原子回滚。
- fresh 验收：WinPS `362/362`、assets `6/6`、scaffold `63/63`、docs `148/148`、capture 顶层 `8/8`、atomic `10/10`、orchestrator `16/16`、树 seal x64/x86 各 `10/10`、Git 精确清理 `3/3`、P4t runner `11/11`；独立安全复审 `P0/P1/P2 = 0`。

## 后果

### 收益

- 来源版本、评估决策、实施目标和验证证据可以独立追踪，来源刷新不会静默改变旧结论。
- 模板保持中立且可复制，具体来源事实只存在于实例；业务运行时与借鉴证据层解耦。
- 显式模式、PowerShell 5.1 门禁和 P4t 契约把关键边界从文字约定变成可重复检查。

### 代价与权衡

- 每次借鉴需要创建来源 capture、事项卡、状态历史和验证证据，操作成本高于直接复制代码。
- 不自动刷新、不执行来源内容会牺牲便利和实时性，但换取确定性、权限隔离和可审计性。
- P4t 的离线检查只能证明本地合同一致，不能替代许可证/权限的人为确认，也不能证明外部来源仍在线或可信。
- 单根与固定 schema 会增加迁移约束；捕获 façade、P4t helper 和契约测试也带来持续维护成本。

### 翻案方式

若未来需要改变单根、capture 不可变、模式标记或验收边界，必须另开 L4 PROP，并用后继 ADR 明确替代范围、历史卡迁移、兼容期和回滚策略。不得直接改写本 ADR、旧 capture 或已关闭事项来伪造连续历史；在后继方案通过完整离线契约与实例验收前，本 ADR 的边界继续有效。
