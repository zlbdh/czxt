## 3. Context loading

### Historical estimate: Claude's 200K-token window ≈ 800KB of Chinese text / 4–5 times as much English text

### Actual per-session loading: five startup steps

| Step | File | Size |
|---|---|---|
| 1 | `agent/INDEX.md` | ~3KB |
| 2 | `状态.md` | ~3KB |
| 3 | Latest pending handoff | 5–10KB |
| 4 | `agent/skills/状态推断*.md` (3 files) | ~15KB |
| 5 | `项目体检*.md` as needed (3 files) | ~17KB |
| **Subtotal** | | **~50KB**, approximately 7% of context ✅ |

### Risk levels

| Scenario | Context use | Level |
|---|---|---|
| Five startup steps | 7% | ✅ Safe |
| Startup + all of agent/ | 25% | 🟡 Caution |
| Startup + all ADRs, RETROs, and PROPs | 28% | 🟡 Caution |
| “Read and summarize every document” | 65% | 🔴 High risk |
| Startup + all application code | 85%+ | 🔴 High risk |

### Protections in place at the time

1. ✅ Five startup steps enforce loading only what is needed.
2. ✅ `状态.md` begins with a summary and links after the PROP-011 simplification.
3. ✅ Handoff cards are separated into pending, accepted, and historical archives after 30 days.
4. ✅ PROP-013's 8KB advisory limits single-file growth.
5. ⚠️ There is no global loading limit; requests such as “read every ADR” can exceed a safe amount.

## 4. Four information channels

### Channel 1: Same tool, different sessions

Session N writes the top summary in `状态.md`; session N+1 must read it at startup, allowing work to resume in about one minute.

### Channel 2: Cross-tool collaboration

1. Tool A completes implementation.
2. It writes a complete six-section card to `交接区/待接手/YYYY-MM-DD-...md`.
3. It sends zlbdh a 5–10-line chat handoff with items ①–⑥, required by PROP-014.
4. zlbdh switches to tool B.
5. Tool B performs the five startup steps, reads the latest pending card, and takes over.

### Channel 3: Long-term decisions (PROP → ADR → RETRO)

A problem signal leads to a PROP, zlbdh approval, implementation, movement to completed status, and an ADR record. Every 3±1 L3+ changes trigger a RETRO. Newly identified patterns feed the next PROP cycle.

### Channel 4: Passive cross-references

Each .md file ends with a Related section pointing to other relevant files, showing the AI where to investigate next.

## 5. Do AI tools remember? Context inheritance

| Tool | Cross-session memory in this historical workflow | Source |
|---|---|---|
| **Cowork** (PM) | ❌ Each new session starts without prior context | Rebuilt through the five startup steps |
| **Claude Code** (Dev) | ❌ Same | Same |
| **Codex** (QA + DevOps) | ❌ Same | Same |
| **zlbdh** (Owner) | ✅ Long-term memory | The user |

The AI tools have no shared memory in this workflow. The filesystem carries information through `状态.md`, the handoff area, ADRs, and other records.

This makes PROP-011's handoff mechanism and PROP-014's mandatory short chat handoff essential information exchanges between tools.

## 6. Strengths and weaknesses

### ✅ Strengths

1. Clear five-layer architecture: knowledge, rules, work, snapshots, and indexes.
2. On-demand loading: about 50KB at startup without overloading context.
3. Established cross-tool exchange: six-section cards and chat items ①–⑥.
4. A complete long-term evolution cycle, with 14 / 18 / 6 PROP / ADR / RETRO records.

### 🟡 Weaknesses: future backlog

1. No topic view; Git-related rules, for example, span three directories.
2. Growing historical archives: 18 handoff cards may eventually become 100.
3. The accepted-handoff list at the top of `状态.md` can grow excessively.
4. No global context-loading limit.
5. No hot/cold memory tiers; all 18 ADRs have equal loading priority.

## 7. Reuse in another project

For a new project building a similar framework:

### Minimum viable version: 1–2 days

- ✅ Cross-session snapshots in `状态.md`.
- ✅ Requirements, decisions, and retrospectives as three record types, even without separate directories.
- ✅ One or two required startup reads: status.md and the latest progress.

### Standard version: 1–2 weeks

- ✅ An `agent/` directory with A/B/C AI boundaries.
- ✅ A PROP / ADR / RETRO lifecycle.
- ✅ A handoff mechanism when multiple tools collaborate.

### Complete version: ongoing evolution

- ✅ Automated project health checks and state inference.
- ✅ Three-level process-first triage and mandatory handoffs.
- ✅ File-size guidance tailored to each tool.
