# Project Structure

This document describes the boundary between governance and the application project. It does not prescribe pages, feature modules, database tables, or build outputs. Verify directory existence and names against the current filesystem and project card.

## Template root navigation

```text
czxt/
├── AGENTS.md                 Five-second entry point for new sessions
├── README.md                 Template overview and initialization instructions
├── 实例化项目.ps1           Initialization with explicit parameters
├── 操作系统/                Roles, architecture, handoffs, ledgers, memory, and workflows
├── 能力资产/                Rules, skills, tools, hooks, and capability inventory
├── PM工作区/                Workspaces for the nine PM roles
├── 交接区/                  Pending, accepted, and archived handoffs
├── 确认改动/                PROP approval state machine
├── Docs/                    General documentation scaffolding and historical governance records
├── 项目配置/                Tracks only _模板.project.json
├── 项目区/                  Local instances and trial installations; actual content is ignored by default
└── 借鉴区/                  Root-level external evidence area
```

The template root does not contain application code, real project cards, release outputs, secrets, or user data.

`借鉴区/` is an external evidence area, not an application dependency. The only execution entry point is the [borrowing skill](../../能力资产/skills/借鉴.md).

## Project instance navigation

The minimum initialized structure is below. Each project defines the contents of `{{APP_REPO_DIR}}/`; the template assumes no particular language, framework, or layering.

```text
{{PROJECT_ROOT}}/
├── AGENTS.md
├── README.md
├── 状态.md
├── TASKS.md
├── 操作系统/
├── 能力资产/
├── PM工作区/
├── 交接区/
├── 确认改动/
├── Docs/
├── 项目配置/
├── 借鉴区/
└── {{APP_REPO_DIR}}/         Application repository; internal structure follows actual project facts
```

Concrete project cards may reside in the project's own local directory or `项目区/本地实例/<project>/`. They are excluded from template repository commits by default.

## Project instance source of truth

| Fact to establish | Preferred evidence | If evidence is insufficient |
|---|---|---|
| Project root and application repository location | Explicit project card and actual directories | Use `[fill in]`; do not infer from directory names |
| Source entry points and module boundaries | Application file inventory, manifest, and runtime entry point | List stable entry points only, not the complete tree |
| Build and test commands | Manifest / CI configuration and actual command runs | Mark as pending verification; do not cite the source project's commands |
| APIs and runtime configuration | Code, contracts, and environment variable templates | Record variable names and authoritative sources, never real secrets |
| Data structures and migrations | Schema/migration files and migration tests | Leave unconfirmed versions as `[fill in]` |
| Build output and release locations | Build configuration and actual outputs | Distinguish tracked files from local artifacts |

Use these read-only commands to obtain evidence of the current directories:

```powershell
rg --files
rg --files "{{APP_REPO_DIR}}"
```

## Maintenance boundaries

- Update this document only when governance boundaries or stable entry points change.
- Use code search or dedicated documents for module, page, table, and function inventories; do not embed them in the template directory guide.
- Historical ADRs / RETROs preserve facts from their time. They do not automatically define the current project structure.
- Always prefix application file references with `{{APP_REPO_DIR}}/` or explicitly state that they are relative to the application repository.
