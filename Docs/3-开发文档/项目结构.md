# 项目结构

本文只说明治理层与业务项目的边界，不预设页面、功能模块、数据库表或构建产物。目录是否存在、名称为何，必须以当前文件系统和项目卡为准。

## 模板根导航

```text
czxt/
├── AGENTS.md                 新会话 5 秒入口
├── README.md                模板产品门面与实例化说明
├── 实例化项目.ps1           显式参数实例化入口
├── 操作系统/                角色、架构、交接、台账、记忆与工作流
├── 能力资产/                rules、skills、tools、hooks 与能力目录
├── PM工作区/                9 PM 工作区
├── 交接区/                  待接手、已接手与历史归档
├── 确认改动/                PROP 审批状态机
├── Docs/                    通用文档骨架与历史治理档案
├── 项目配置/                只追踪 _模板.project.json
├── 项目区/                  本地实例与试装入口；真实内容默认忽略
└── 借鉴区/                  根级外部证据层
```

模板根不承载业务代码、真实项目卡、发布产物、密钥或用户数据。

`借鉴区/` 是外部证据层，不是业务代码依赖；执行入口仅为 [借鉴 Skill](../../../能力资产/skills/借鉴.md)。

## 项目实例导航

实例化后的最小结构如下；`{{APP_REPO_DIR}}/` 内部由项目自己定义，模板不假定使用哪种语言、框架或分层：

```text
{{PROJECT_ROOT}}/
├── AGENTS.md
├── README.md
├── 状态.md
├── TASKS.md
├── 操作系统/
├── 能力资产/
├── PM工作区/
├── 交接区/
├── 确认改动/
├── Docs/
├── 项目配置/
├── 借鉴区/
└── {{APP_REPO_DIR}}/         业务仓库；内部结构以项目实例真值为准
```

具体项目卡可以放在项目自己的本机目录，或 `项目区/本地实例/<项目>/`；默认不提交到模板仓库。

## 项目实例真值

| 要确认的事实 | 首选证据 | 不足时怎么写 |
|---|---|---|
| 项目根与业务仓库位置 | 显式项目卡 + 实际目录 | `[填写]`，不要按目录名猜 |
| 源码入口与模块边界 | 业务仓库文件清单、manifest、运行入口 | 只列稳定入口，不复制整棵文件树 |
| 构建与测试命令 | manifest / CI 配置 + 命令实跑 | 标为待验证，不引用来源项目命令 |
| API 与运行配置 | 代码、契约、环境变量模板 | 只写变量名与真源，不写真实密钥 |
| 数据结构与迁移 | schema / migration 文件 + 迁移测试 | 未确认版本保留 `[填写]` |
| 产物与发布位置 | 构建配置 + 实际产物 | 区分 tracked 文件与本地产物 |

推荐用以下只读命令取得当前目录证据：

```powershell
rg --files
rg --files "{{APP_REPO_DIR}}"
```

## 维护边界

- 本文件只在治理层边界或稳定入口变化时更新。
- 业务模块、页面、表和函数清单应由代码搜索或专门文档承接，不写进模板目录导航。
- 历史 ADR / RETRO 保留当时事实；它们不会自动升级为当前项目结构。
- 引用业务文件时始终带 `{{APP_REPO_DIR}}/` 或明确“以业务仓库为基准”。
