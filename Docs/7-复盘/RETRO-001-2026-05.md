## 2. What worked

- **Audit before implementation:** after finding zlbdh's existing `rules/` and `Docs/` framework, we switched from option B, rebuilding, to option C, incremental additions, preserving existing work.
- **Use mv for L4, rather than cp/rm:** preserved timestamps and inodes, completed in under a second, and avoided reinstalling node_modules.
- **Put AI proposals in `确认改动/待审批/` first:** PROP-001 followed the approval workflow without altering the PRD.
- **Static bracket and import checks as an esbuild fallback:** useful when the sandbox could not run the Linux esbuild binary.
- **Update ADR/CHANGELOG/technical breakdown with each L3+ change:** the DoD checklist prevented missing documentation.
- **Pause and ask zlbdh before irreversible actions:** deleting empty directories and moving code were approved first.
- **Respond to mount truncation with Python:** used `errors='replace'` to read damaged content, identify the loss, and restore it through a Python heredoc.

## 6. Main lessons

Framework updates, L3 code, an L4 refactor, and incident repair were completed in a single three-to-four-hour session.

The largest lesson was that Edit could not be trusted and the then-current rule required Python above 6 KB. Framework instructions should specify the verification action before its subject.

The layered layout, `{{APP_REPO_DIR}}/` + `rules/` + `Docs/` + `确认改动/`, reduced the root from 22 entries to seven. zlbdh's question about the clutter triggered the L4 improvement and delivered the session's largest return.

The session's ADRs, proposals, technical breakdown, and documentation establish a baseline for subsequent work. RETRO-002 was planned after completion of the seven remaining L3 requirements in Sprint 1.
