## Seven recurring insights

### 1. Self-correction proves a rule works

PROP-007 introduced the ≥6500 B rule; PROP-009 violated it; Claude Code's health check caught it; PROP-010 fixed it. The cycle closed in under 24 hours. Trigger conditions and response speed demonstrate actual effectiveness.

### 2. Cross-tool friction concerns information flow

zlbdh clarified that the issue was state and information flow, not copying and pasting. A three-section packet forced recipients to infer too much. Six sections covering files, tests, next steps, cautions, and questions supplied useful detail. Collaboration becomes effective at the right granularity.

### 3. Tool behavior differs even under identical instructions

Claude Code automatically read screenshots into chat, eventually hitting API image limits above 2000 px and "Could not process image" errors. Codex saved screenshots to files without automatically reading them back. Claude Code's tool workflow could not follow the same save-without-chat instruction. The DoD capability matrix must record output side effects, not only whether an operation can run.

### 4. Mount caching undermines Bash verification

After Edit, Bash wc -c and grep could lag several minutes. This recurred in v9, v15, v17, v20, and v23. Critical state requires Read verification, as documented in health/state-inference known-limitations sections.

### 5. Cross-tool proposal relays are a new pattern

Codex wrote PROP-008 and handled code splits; Claude Code completed formal closure. This relay needed a standard handoff, supplied just in time by PROP-009: PROP-008 began, PROP-009 completed, and PROP-008 then closed using the new format. Dense change periods accelerate process evolution.

### 6. The DoD reconciliation skills found real defects

The two reconciliation skills, health check, and state inference caught PROP-009's 7029 B overflow, proposal/decision tracking issues, and the large-file warning band. These checks were operationally useful, not merely ceremonial.

### 7. Four L3+ refinements indicate maturation

RETRO-001 covered large structural changes such as the application migration and rules→agent transition. RETRO-002/003 strengthened workflows. RETRO-004 focused on self-correction and incremental refinement. Decreasing change depth was a convergence signal.
