2. **Both LLM directions shipped that day.** F-BRIEFING-1 generated output briefings, while F-DEVIATION-2 classified input. Development-mode default configuration, dual fallback paths, a one-hour cache, three modes, and network-panel visibility all shipped together.

## Problems

### 1. F-PREP-1 smoke 07: Number("") became zero

Leaving a custom decimal-item threshold blank produced 0 instead of the PRD default 0.2. Empty/default behavior was insufficiently specified, repeating RETRO-007 problem 1. Promote issue P to P0: require an explicit PRD section for empty states, defaults, and Number() boundary cases.

### 2. Missing API configuration blocked successful LLM smoke tests

F-BRIEFING-1 returned 401, preventing device verification of the success path. Development-configuration automation was missing. Historical issue V addressed this through development defaults and six safeguards.

### 3. Thinking consumed the token budget

The mimo-v2.5-pro thinking model exhausted maxTokens=200 before producing JSON. Regex fallback hid the failure. Mocks did not simulate this LLM error. New issues AD/AE covered exceptional LLM mocks and centralized LLM_DEFAULTS_BY_USE_CASE.

### 4. A real API key was disclosed in chat

An explicit user override resulted in a key being pasted into the conversation. The mitigation was key rotation, completed in ten seconds after Sprint-4 closure under issue X-A. Promote issue X to P0 for real-secret disclosure rules and rotation handling. No credential value is reproduced here.

### 5. Mount-cache incidents reached nine or ten trials

## Meta-level insights

1. **Ship, then organize worked within the agreed scope.** Despite eight size warnings, PM chose option A: finish Sprint 4, then make the actual repairs after RETRO-008. The 5/5 closure supported distinguishing business urgency from tool warnings, issue N. Reversing direction repeatedly was identified as a major framework-stability risk.
2. **PM corrections rose from 16 through 37, recorded as 22 corrections.** Corrections 19/20 reprioritized useAppData at 8014 B from P0 to P2; 21/22 reprioritized anomalyDetector at 9070 B from P0 to P1; 27 mitigated llmBriefing's nine-byte margin without changing it during Sprint 4; 36/37 recognized that static health checks cannot predict runtime smoke results. Issue N, P1, should formalize separating tool warnings from business urgency.
3. **Quality-gate depth increased.** The detailed history lists F-PLAN-1's UI empty state in Sprint 3, then F-PREP-1's Number boundary, F-BRIEFING-1's API prerequisite, and F-DEVIATION-2's network/user-experience discrepancy in Sprint 4. Codex's role expanded from checklist execution to cross-layer quality judgment.
4. **LLM work increased test-file size and exposed weak mocks.** All four *-llm.test.js files exceeded 10 KB. Mocks omitted thinking models, stop reasons, and token limits. Passing Vitest did not establish passing device smoke. Issue AD, P1, covers stronger mocks and test splitting.
5. **Self-governance came from repeated evidence.** Zero dead/low-reference files, a fresh state snapshot, self-detected CHANGELOG overflow, and nine or ten mount incidents showed the framework evolving through failures, detection, and repair rather than prose alone.
6. **Conditional rule changes followed a repeatable historical process.** PROP-012 and issue V combined explicit zlbdh direction, six safeguards designed by PM, separate PROP/ADR records, and retrospective verification. The original record suggested using this process for later proposals, including a hypothetical AI commit-message rule change. It does not authorize bypassing current safety boundaries.
