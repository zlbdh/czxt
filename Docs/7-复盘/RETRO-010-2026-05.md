## Lessons

1. **Acceptance criteria need evidence.** Numeric constraints for length, duration, or frequency should avoid arbitrary single hard limits. Use structural requirements, soft numerical guidance, and postprocessing where appropriate; consider explicitly allowing adjustment after device evidence.
2. **Verify before inference, version 3.** BR's model identity, BP's 401 diagnosis, F-DIARY-1's UI proposals, and the master shipping template showed the same pattern four times. The historical text called this three feedback-memory items: `feedback_pm_no_default_inference.md`, `feedback_pm_verify_ui_first.md`, and candidate CD's pre-shipping checklist covering branch, module entry points, and tabs.
3. **A thinking-model token budget is not an output-length control.** MiMo with max_tokens=150 could return empty replies after multiple turns, unlike a nonthinking model. Use runtime postprocessing such as normalizeNightReply for length. Codex found this through device evidence; PM had missed it during PRD design. Candidate CE proposed a model-type/prompt-pattern mapping.
