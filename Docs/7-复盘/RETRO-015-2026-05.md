## 4. Key findings

### 1. ⭐ Large-file mount operations can return stale reads or truncate writes; Read was the only trusted channel

Three failures occurred that day: #92 checked verification tools through Read rather than running the complete device verification, leaving bugs undetected; #94 truncated a 21KB file through Edit; and the 84KB 状态.md appeared incomplete or stale through the mount, including a Python decoding error, bash tail ending at L589, and grep false negatives. ADR-025 covered stale reads only. **Truncated writes and reliance on the Read tool as the sole source of truth added a new dimension**, proposed for ADR-033.

### 2. Verification tools must themselves be verified: #92

Leaving device verification to zlbdh creates verification debt. Testing only a newly added section without running the full check on the device allows older defects to survive. **After changing framework tools, run the complete check on the actual machine.**

### 3. Source-grep contracts and file splitting need an advance exception for moved grep targets: #95

Chat.test.js asserts source-grep contracts. Requiring both zero test changes and files below 8KB was mathematically incompatible. Claude Code caught the conflict, escalated it, and option A was selected: move grep targets with the code while preserving assertions. Issue CD's PM handoff checklist needs a source-grep test-contract dimension.

### 4. ✅ First complete application release through the cross-tool nine-PM process

Technical PM in Cowork wrote the handoff → Development PM in Claude Code identified and escalated conflicting criteria instead of forcing implementation → Project PM in Cowork decided → Test and Release PM in Codex ran device checks and shipped → Cowork archived the work. **Issue CD's safeguard worked; zero application incidents; v4.0 passed this application-release validation.** The record contrasts this with earlier framework-governance releases.

### 5. ADR-031's prediction of zero Sprint-11 recurrences was not met: #93 recurred once

RETRO-014 predicted zero recurrences after ADR-031. In practice, #93 replaced a decision with a question, triggered by zlbdh's reminder that the assistant was Project PM. The rule was complete; execution failed in a polite closing question. The self-check: if a closing “Would you like me to...?” obviously has the answer yes, remove the question and act.
