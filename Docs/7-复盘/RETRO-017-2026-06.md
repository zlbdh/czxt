## ✅ Four repeatable successes

1. **Debt-reduction patterns.** EventCard fell from 8059 to 4086 bytes, −49%; AlarmCard from 8109 to 4691, −42%. Twice, dangerously narrow 83–133B headroom became a healthy 3.5–4KB. Repay debt before features: splitting EventRow enabled single-day management; splitting AlarmCard enabled naps. Pure refactoring moved state and handlers without effects/timers, with design-stage #95 prevention and zero collisions.
2. **⭐ First integration of ultracode adversarial review.** Data/safety changes demonstrated its value. Expired-item cleanup review caught stale `armedClear` state: after background synchronization changed empty data to populated data, one click could bypass the second confirmation, crossing a Class C boundary. Allergen review exposed protection on only one of five paths and disproved the PM handoff's premise. Both real defects were caught before release. Data-deletion and food-safety changes require adversarial review.
3. **Pattern reuse stayed fast and stable.** A's skincare v3.21, training v3.26, and allergens v3.29 reused the SkincareSection structure; mealRecommend informed skincare recommendations; kneeIssue informed equipment filtering. Reused patterns required no rework and had predictable file sizes.
4. **Subagent investigation continued correcting PM assumptions.** It disproved the claim that G would unlock skincare recommendations when G had no code, established that a supposedly pending nap reminder already existed, placed allergens in meals rather than skincare, and compared two equipment routes, one conflicting with K-F8. Investigation before setting scope catches PM's incorrect premises.

## 📚 Lessons proposed for the meta-rule pool

### 1. 🔴 Define when investigation may be skipped: the batch's most important PM correction

Under the fast pace, PM repeatedly issued handoffs without investigation. Evidence established the boundary: pure pattern reuse such as v3.24/v3.26/v3.30 could proceed directly. However, the allergen handoff assumed mealRecipe naturally inherited avoidance and required zero changes, without verification. Adversarial review disproved this: only one of five allergen paths was protected; recipes, shopping, fallback, and chat were all exposed.

**Rule:** Any handoff claim of “zero changes,” “naturally inherited,” or “downstream behavior automatically satisfies this” is a #54-style internal-consistency check requiring grep verification. Changes with a **new implementation destination** cannot skip investigation.

### 2. 🔴 Require adversarial review for data/safety changes

Expired-item cleanup and allergens each produced a real finding: a Class C boundary leak and four unprotected paths out of five. Pure refactoring or pattern reuse could skip review proportionately; v3.23/v3.30 did so with zero issues. **Changes involving user-data deletion, health/food safety, or irreversible actions require adversarial review.**

### 3. 🔴 A review-driven scope-expansion example

For allergens, the implementer completed the handoff, then adversarial review disproved its premise and found a safety gap. The implementer transparently expanded coverage to all five paths and requested PM review. PM approved and recorded its own correction.

**Pattern:** When all acceptance criteria pass but the scope is unsafe, the implementer should neither expand silently nor ignore the issue. Make the expansion explicit, document it, and request review. PM takes responsibility for its incorrect premise.

### 4. Escalating mount failures prompted a formal pre-commit Git check

Proposed ADR-025 addendum. Failure frequency and severity reached a new high: index.lock repeatedly resisted removal; git status showed contradictory ghost entries, including deleted configuration and storage-shim simultaneously marked RD/??; false `Bin 8059→8059` output; and null sha1.

The effective response was: Codex checks `git status --short` in the actual shell before committing. Two cases confirmed a clean real working tree and corruption confined to Cowork's view. The implementer added this Git gate to the release handoff, making it routine. On the Cowork side, trust Git metadata and `git show HEAD`; wc/Read were unreliable for previously read files.
