## 2. What worked

1. **One output-contract change fixed three paths in r3.** Defining required output markers instead of how the model should think immediately passed chat, recommendations, and recipes. Verifiability is the first design consideration for an LLM feature.
2. **Evidence before fixes in r4.** The implementer followed PM's instruction to gather evidence rather than change things blindly. Four real calls, including deterministic rich-profile reproduction and validation of the proposed value, established the cause. One constant ended three rounds of back-and-forth.
3. **The implementer disproved a PM suggestion with evidence.** Rejected an item-limit sentence because more prompt text induced more thinking and made the problem worse. This was the second healthy example of a subordinate challenging PM, after v3.29's scope expansion.
4. **Mandatory ultracode review for data/safety work was applied.** It repeatedly caught real MAJOR issues: a spicy-food avoidance contradiction resembling W-3 recency and gaps in the three-prohibition boundary. All were fixed before release.
5. **Controlled Codex verification addressed UI randomness.** Four random recommendations never selected light soy sauce, so a controlled shopping call verified low-sodium light soy sauce, reduced-salt soy sauce, and low-salt MSG with zero brands.
6. **Release rules held across all four rounds.** No failed version was committed, tagged, or pushed.

## 3. What blocked progress

1. 🥇 **No visible-marker acceptance criterion for an LLM behavior constraint.** Smoke tests had nothing observable to verify, causing three rounds of rework, the batch's largest cost. Sodium control was hidden behavior. The first handoff should have specified what the output must say and approved its smoke criterion together.
2. **“Replace” caused seasonings to disappear in two rounds.** Prompt verbs behave like APIs: replacing saltiness with acidity was interpreted as removing sodium-containing seasonings from the list. Action verbs such as replace/delete/avoid need explicit limits: do not replace the original seasoning; supplement it only.
3. **A general maxTokens minimum of 4000 was insufficient.** With thinking models and accumulating injections, the required budget depends on the path. Shopping had been operating at 82–96% of its limit; each r1–r3 injection increased thinking until rich device profiles failed while simple profiles still passed.
4. **Prompt injection consumes a shared budget across paths.** Each block added to the same LLM call consumes thinking capacity for every scenario. Track injection text size globally.
5. **Rehearse what perfect compliance would produce before setting smoke criteria.** In r2, shopping replaced sodium-containing seasonings with lemon, ginger, scallions, and garlic, perfectly following “replace”; the verification criterion therefore had no matching output.
6. The review harness crashed once because the lens produced no structured output. The implementer did not release blindly and proactively removed the targeted contradiction. The response was acceptable; record it without turning it into a routine exception.
