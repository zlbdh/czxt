## 2. What worked

1. **Three consecutive deterministic changes passed in one round:** posture, HIIT, and the week view. After four sodium-control rounds and five G-F6 rounds, alternating prolonged LLM work with deterministic changes restored delivery speed.
2. **🥇 Established the hardening-guard pattern in G-F6 r4.** Canonical machine-readable dates such as day N of every month or month M/day N of every year use **regex as the authority and the LLM as fallback**, expressed by the historical implementation as `extractRecurrenceFromText(原文) || normalizeRecurrence(raw)`. Reversing that order was wrong. This ended the incorrect or missing recurrence values seen on devices in rounds 2–4.
3. **Reduce file-size debt before adding the feature.** For the week view, Home was 8199B, above the limit. Extracting its banner shell verbatim reduced it to 7579B before adding functionality. The handoff stated this as a prerequisite and the implementer followed it automatically.
4. **Use wall-clock anchors for HIIT.** Timing accuracy was central to the experience. Derive state from elapsedMs instead of accumulating tick-minus-one updates; this self-corrects after backgrounding and supports unit tests. Smoke evidence showed the remaining time change from 25s to 9s.
5. **Continue evidence-first investigation.** Each G-F6 round used real-shell calls to isolate device-specific failures after Node passed; no blind fixes.
6. **Release rules held through five G-F6 rounds.** No failing version was committed.

## 3. What blocked progress

1. 🥇 **Align vocabulary across every layer when changing any multilayer gate:** regex prescreen → prompt classification → normalization → fallback. In G-F6 r1, haircut/dental-cleaning terms were added to the first regex layer but omitted from the second prompt-example layer, repeating v3.20's follow-up-appointment failure. Every added trigger term must be verified across the entire chain.
2. **Node passing while devices fail creates recurring investigation cost.** All five G-F6 Node calls passed while devices repeatedly failed; MiMo's device-side response variations did not reproduce in Node. The durable solution was deterministic processing, moving the LLM out of the critical path, plus DEV logcat evidence of actual device values—not endless Node-only reproduction attempts.
3. **PM asserted unverified behavior in the handoff: another #54 pattern.** The G-F6 PRD claimed that LLM rules ①/⑥ already supported haircuts and dental cleanings. This was inferred from inspection without a real call and caused r1 failure. Inspection-based inference is not demonstrated behavior; mark LLM assertions as awaiting smoke verification.
4. **LLM output should not have been in this critical path.** The canonical recurrence format was already machine-readable. Regex should have been authoritative from the first change instead of requesting recurrence from the LLM. This complements RETRO-018's visible-marker lesson: **prefer regex for structured machine-readable fields.**
