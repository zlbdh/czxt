## 2. What worked

1. **🏆 Established a safe schema-migration pattern in two changes.** `V_N_STORES = {...V_{N-1}_STORES, newTable}` plus `db.version(N)` **without .upgrade()**; add the table to exportAllData; tolerant loadSnapshot; initial-state fallback; and device smoke testing that creates data in the old version, upgrades over it, and checks every old table. Both v15/v16 upgrades lost no data. The schema-less sequence could be deliberately and safely ended.
2. **Privacy review for M's sensitive behavior data.** The ultracode privacy lens checked minimization by truncation, code-point handling to avoid splitting emoji, local-only storage, user-controlled deletion, and nonjudgmental language. Its finding that every record needed deletion controls was valuable near the Class C user-data boundary.
3. **Deliver the deterministic portion of a larger investment first.** M's first stage recorded without learning, writing the existing detectionResult with no extra LLM call. Leave LLM learning for later instead of immediately following a substantial schema change with prolonged LLM iteration. This applied RETRO-019's pacing lesson.
4. **Food-safety review continued finding substantive issues.** The lunchbox review identified the rice/Bacillus cereus toxin concern, described as fried-rice syndrome; reheating did not remove the cited toxin risk. The issue was addressed before release.
5. **Third and fourth examples of reducing file-size debt first:** the week view's Home banner extraction and M's chatSuggestionSelect extraction. The implementer applied the pattern automatically.
6. **Deterministic changes continued passing in one round:** travel, weight curves, lunchboxes including review, and M. No release-rule failures.

## 3. Lessons and observations

1. **Snapshot handling in both directions is a hidden part of a schema bump.** A new table can be safe while omission from exportAllData loses its data in backups, near the Class C boundary. Acceptance criteria plus ultracode caught this in both changes. Formalize the four required locations: schema/exportAllData/loadSnapshot/initial.
2. **Stale-mount wc persisted.** Each change showed old byte counts. Positive grep matches plus Git's modified status were the trusted evidence. This verification approach was stable and nonblocking, but still consumed effort.
3. **Near-limit central files were accumulating:** useAppData 8184, snapshot 6798, and useChatController 7850 after extraction. Data changes repeatedly touch these modules; extract before the next modification.
4. **The directly actionable small-change backlog was depleted.** A/D/F/G/H/I/K were clear, and the principal B/C/E/M work had shipped. Learning, daysLeft, holidays, and J/P2 were investment-level tasks. The project had reached substantial core completion.
