# RETRO-021 · First PROP-044 B-lite Controlled Framework Concurrency Trial

> Date: 2026-06-14. Trigger: PROP-044 AC3, a real large framework batch with parallel workers, and AC4, an assessment of ADR promotion after the trial. Type: focused framework governance, not a Sprint batch.

---

## 1. Work against PROP-044 acceptance criteria

- **Previously implemented:** zlbdh approved **B-lite controlled concurrency** for PROP-044. This was incorporated into `子agent调度机制.md` §3.5, `角色边界.md`, and the dispatch card's disjoint-write-set declaration, AC1/AC2.
- **AC3 trial:** Project PM dispatched **three actual concurrent workers** to add missing scope frontmatter to **26 Markdown files** under `能力资产/`, addressing real PROP-037/ADR-028 debt:
  - Worker A: `rules/`, 11 files, project/semantic/on-demand.
  - Worker B: `skills/`, nine files, project/procedural/on-demand, with one triggered file.
  - Worker C: `shared/+tools/+mcp/`, six files, project/semantic/on-demand.
  - Write sets were **disjoint by subdirectory**. All three workers were dispatched concurrently in one message.
- **Main-session integration and health gate:** independently confirmed exactly 26 changed files, untouched no-parallel sentinel files, and intact sampled bodies. `check-operating-system.ps1` exited **0**, with P4a–P4h passing, before acceptance.
- **AC4:** this retrospective.

## 2. What worked

1. **Disjoint subdirectory write sets produced zero races or boundary violations.** The count of framework files still missing frontmatter fell exactly from 61 to 35, 61−26. No out-of-scope writes were found. The sentinel files `角色边界.md` and `CHANGELOG.md` still began with `#`, showing workers had not touched them.
2. **The write-set declaration and explicit no-write list, including shared single-source files, worked.** No worker touched `状态.md`, `交接区`, `CHANGELOG`, `元规则池`, or `角色边界`. AC2's new field was demonstrated in practice.
3. **Specify direction without prescribing every method.** Worker A chose Edit rather than Write to preserve bodies more reliably. Worker B correctly chose `loaded: triggered` for `状态推断-跨session监控`. Judgment room let workers improve the brief's suggested method.
4. **The health check worked as an acceptance gate.** P4f tracking, P4g counts, and P4h anchors were checked automatically. Only exit 0 was accepted; zero false negatives were observed.
5. **Independent scope probes were inexpensive.** A single count comparison—remaining framework files equal the original count minus assigned files—provided a strong scope check.

## 3. Problems and inefficiencies

1. 🔴 **Barrier waiting wasted time.** A took 79s, B 305s, and C 55s. Parallel wall time was therefore approximately **305s**. A/C finished early but waited roughly 226s/250s. Dividing by file count, 11/9/6, overlooked that skills were larger and needed more judgment. B became the bottleneck. Balance controlled framework concurrency by **estimated work**, not merely file count, or use a pipeline to remove the barrier.
2. 🟡 **Verification has a real cost.** Independent main-session scanning, sampling, and health checks required approximately 2–3 steps. This was worthwhile for 26 files; for 6–8 files, verification may consume the concurrency benefit. This supported §3.5's minimum of six files and suggested it might even be raised.
3. 🟡 **Cosmetic spacing:** some files had two blank lines after frontmatter because worker prepending combined with an existing blank line. Harmless in rendered Markdown, but a future brief could request consistent spacing.

## 4. Standard changes and ADR assessment

**Recommendation: do not create a separate ADR yet. Mark this as an ⭐ ADR candidate and gather another one or two practical trials first.**

1. Meta-rule promotion requires at least three occurrences of a pattern plus retrospective assessment. This was the **first** trial and only one data point.
2. B-lite was already an **effective, binding rule** in §3.5 under approved PROP-044, regardless of ADR promotion.
3. An ADR creates a foundational commitment. Verify the mechanism across **two or three different framework batch types**, such as bulk link repair or playbook additions, rather than frontmatter alone.

**Candidate meta-rules for later trials. These require PROP before implementation; this retrospective records observations only:**

| Candidate | Content | Evidence |
|---|---|---|
| **DU** | Balance controlled framework workers by estimated work, not file count, or remove the barrier with a pipeline | B's 305s duration left A/C waiting. |
| **DV** | Add a low-cost scope probe: changed-file count equals the total assigned count. Consider the §3.5 acceptance checklist or P4i | Exact 61−26 count verification. |
| Observation | Keep the current minimum of six files in §3.5 after one trial; verification-cost evidence supports it | This trial's verification overhead. |

**ADR trigger:** at least another one or two successful trials on different framework batch types, with accumulated DU/DV evidence. Then create a PROP for ADR promotion, extending ADR-027's subagent scheduling or creating a new ADR.
