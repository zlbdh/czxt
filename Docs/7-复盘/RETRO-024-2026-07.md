## 二、哪里顺（值得保留）

1. **先取证再改，避免把“看起来干净”当完成**：对 hooks 不只看终端 PASS，还在运行前后枚举 literal 临时目录，才发现 exit 0 背后的 9→10 泄漏。资源集合差异补上了原测试没有观察的维度。
2. **RED/GREEN 覆盖了第二层风险**：第一版“按 prefix 做前后差集再清理”能消除泄漏，却没有所有权边界；新增并发同前缀 sentinel 后先稳定复现误删，再改为唯一 TempRoot + 精确路径清理，修复对象从“当前残留”上升到“资源所有权”。
3. **独立复审对语义越界有效**：复审既抓到 prefix 清理会误删并发目录，也抓到角色 playbook 被过度改写。后者已恢复为 HEAD + 2 行边界，说明多文件文案优化仍需要用权威白名单反向验收，不能只看措辞是否更通用。
4. **P4s 只守当前真值，不重写历史**：以目标文件 + 必需 / 禁止锚点做定向检查，允许历史 ADR / RETRO 保留 React、Dexie 等当时事实，降低全局关键词门禁误伤历史证据的概率。
5. **阶段与发布口径诚实**：明确 P1 已完成、P2 未完成；也明确 HEAD 与本地 `origin/main` 相等不等于远端实时同步。本轮没有把未授权的 commit / push 包装成“已收口”。

## 三、哪里卡（坑 / 低效 / 流程偏差）

1. **🔴 smoke PASS 但资源泄漏，是典型假绿**：旧 contract 只断言 hook 输出，没有断言 fixture 生命周期；因此功能契约全通过时，临时目录仍永久残留。测试如果创建外部资源，验收必须同时看行为结果和资源回收结果。
2. **🔴 prefix 不是所有权证明**：初步修复通过扫描同前缀目录的 before / after 差集来删除“新增项”。并发测试或另一个进程只要创建同前缀目录，就可能被本轮误删。名称相似不能替代“由本测试创建并持有精确路径”的所有权证据。
3. **🟡 当前真值缺少机械边界，语义漂移能长期积累**：P1 / P2、ADR 数量、固定模型 / endpoint、来源业务 schema 分散在多个当前入口；原 P4s 只抓少量专名，无法识别“文件位置正确但语义仍是来源快照”的漂移。
4. **🟡 模板中立化容易滑成角色重构**：首轮对 playbook 的通用化超出了 PROP-003 的边界，实际触及权威路径白名单语义。Q1-Q7 虽然跑过，但单看“项目实例真值”这个目标仍不足以阻止内容层扩边；独立复审才把它拉回。
5. **🟡 P4s 已到 7773B，逼近 Codex 8KB 软建议**：本轮仍低于上限且职责可读，但再继续往同一文件追加当前真值清单，会增加审查成本并削弱单一职责。现在应记录拆分评估点，而不是等越线后被动拆。

## 四、要不要改规范 / action item

> 本 RETRO 只记录观察与后续动作，**不直接改规则，不新起 PROP / ADR**。是否进入规范变更，由后续项目 PM 按 Q1-Q7 另行判定。

| action item | 可执行完成标准 | 优先级 | 本轮处理 |
|---|---|---|---|
| **fixture 精确所有权** | 所有新 hooks fixture 由调用方生成唯一精确路径；被调函数只清理自己收到 / 创建的 `LiteralPath`；共享前缀场景至少保留一个并发 sentinel 反例 | P1 | Claude lifecycle 已落地样本；后续新增 fixture 时复用，是否上升为通用规则待评估 |
| **当前真值守卫登记** | 新增或改名“当前入口”时，同步评估是否加入 P4s 定向清单；历史档案不做全局禁词；门禁失败必须输出文件、行和缺失 / 禁止锚点 | P1 | PROP-003 已建立首批清单；后续只按真实漂移证据扩展 |
| **P4s 拆分评估** | 下一次扩充 P4s 前先量字节和职责；若继续增长或超过 8KB，将通用读取 / 断言函数与当前真值清单拆成独立子模块，并保持 façade 输出兼容 | P2 | 当前 7773B，先记观察点，不在本 RETRO 直接拆 |

**升 ADR 评估**：本轮没有新的架构决策。唯一 TempRoot、定向守卫和 playbook 恢复都是现有测试隔离、路径白名单与历史安全边界的具体落实，不另立宪法。
