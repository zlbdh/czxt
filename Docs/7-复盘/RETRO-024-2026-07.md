## 2. What worked

1. **Gather evidence before changing anything.** Checking terminal PASS alone would have missed the hook leak. Enumerating literal temporary-directory sets before and after exposed growth from nine to ten despite exit 0. Resource-set comparison added an observation missing from the original test.
2. **RED/GREEN exposed the second risk layer.** The initial fix removed newly observed prefix-matching directories and stopped the leak, but lacked ownership proof. A concurrent same-prefix sentinel reliably reproduced unintended deletion. Unique TempRoot plus exact-path cleanup shifted the fix from removing leftovers to respecting resource ownership.
3. **Independent review caught semantic boundary violations.** It found both unsafe prefix cleanup and overbroad playbook rewrites. Restoring HEAD plus two boundary lines showed that wording improvements across files need validation against authoritative allowlists, not just a judgment that the prose sounds more general.
4. **P4s protects current facts without rewriting history.** Target files and required/forbidden anchors allow historical ADRs/RETROs to retain facts such as React and Dexie. This reduces false positives from global keyword bans against historical evidence.
5. **Stage and publication claims stayed honest.** P1 was complete and P2 incomplete. HEAD matching local `origin/main` did not establish real-time remote synchronization. No unauthorized commit/push was described as completed work.

---

## 3. Problems and process deviations

1. 🔴 **Smoke PASS with a resource leak is a false green.** The old contract asserted hook output but not fixture lifecycle, leaving temporary directories indefinitely despite functional success. Tests creating external resources must verify both behavior and reclamation.
2. 🔴 **A prefix does not prove ownership.** Deleting the difference between before/after prefix scans can delete a directory created concurrently by another test or process. Similar names cannot replace proof that this test created and holds the exact path.
3. 🟡 **Current-fact boundaries lacked mechanical enforcement.** P1/P2 status, ADR counts, fixed models/endpoints, and source-application schemas were scattered across entry points. The old P4s checked only a few names and missed documents in the correct location whose content still described the source snapshot.
4. 🟡 **Template generalization can drift into role redesign.** The initial playbook rewrite exceeded PROP-003 and changed authoritative allowlist meaning. Q1–Q7 had run, but the goal of project-instance truth alone did not stop broader permissions from entering the content. Independent review corrected it.
5. 🟡 **P4s reached 7773B, near Codex's 8KB guidance.** It remained under the limit with understandable responsibilities, but adding more current-fact checks would increase review cost and weaken separation of concerns. Record the split-assessment point now rather than waiting for a forced split.
