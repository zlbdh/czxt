# PM Self-Correction #75 — Root tools/ Conflicted with Capability tools/

> **Time:** 2026-05-22 15:30.
> **Trigger:** zlbdh asked why both `{{PROJECT_ROOT}}\能力资产\tools` and `{{PROJECT_ROOT}}\tools` existed.
> **Issue:** CM v3.2, naming lagging behind design; third occurrence.
> **Related cases:** #60 changed the memory-center name to workspace; #61 aligned role filenames and workspace names; #75 concerns a top-level collision.

## 1. Mistake

During tasks #90–#92 early on May 22, implementing the complete PROP-027 v2 improvement 2, I created `{{PROJECT_ROOT}}\tools/` for executable PowerShell scripts, including check-operating-system.ps1 and check-pm-tracking.ps1, without checking for the existing `能力资产/tools/`.

PROP-028 had already created `能力资产/tools/` on May 21 for Markdown declarations such as `构建脚本.md` and `依赖矩阵.md`.

The root directory held executable PowerShell code, while the capability directory held declarative Markdown documentation. Sharing the name `tools/` made their responsibilities ambiguous.

## 2. Causes

1. Before creating a top-level directory, I did not check collisions with `ls -d`, inspect `能力资产/tools/`, or search existing tools references. I went straight to `mkdir tools && ...`.
2. Knowledge PM “Curator” performed repeated framework health and role reviews in tasks #102–#108, but checked existence rather than top-level naming collisions.
3. Issue CM covered names that no longer matched intent (#60) and filename/directory mismatches (#61), but not top-level ambiguity.
4. The record's naming convention favored `scripts/` for executable scripts—npm, shell, and GitHub Actions—while `tools/` described tool governance. The chosen name obscured that distinction.

## 5. Lasting lesson

Before creating a top-level directory, follow the #75 checklist intended for Knowledge PM's quick references:

```text
1. ls -d <target_dir>                       # Check direct collision.
2. find . -type d -name "<name>"             # Check the entire project.
3. grep -r "<name>" --include="*.md" | head # Check README references.
4. Compare conventions: scripts/, tools/, lib/, bin/, etc.
5. Does the name communicate intent or merely form? Apply lesson #60.
```

- v2: filename/directory consistency, #61.
- v3.2: top-level collisions and convention checks, #75.
