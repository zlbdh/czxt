See [role boundaries](01_架构/角色边界.md) and the [agent index](02_智能体/README.md).

### Agent scheduling quick reference: 2026-06-14 / ADR-038

- A PM defines responsibility and authority; an agent is a temporary execution instance.
- Except for the Project PM's main session, each PM's actual work defaults to a real agent: writes use workers; read-only diagnosis uses explorers.
- Project PM “Mimi” owns centralized scheduling and acceptance. Spawn authority is not delegated: other PMs may request agents but must not spawn them independently.
- Agents may only draft single-source files that prohibit parallel writes. The main session makes the final write. Release actions remain with one owner and must not be delegated.
- See the [agent scheduling mechanism](01_架构/子agent调度机制.md).

## 6. Maintenance procedure

- **When to synchronize**: before a Sprint RETRO, after a framework PROP is implemented, when an issue is permanently closed, or when the nine-PM matrix is upgraded.
- **Owners**: Operating System PM “Framework Steward” for framework governance, plus Knowledge PM “Curator” for cross-PM oversight.
- **Evolution principle**: the three expansion questions in [evolution philosophy](01_架构/演化哲学.md) apply specifically to adding PM roles; they do not replace Q1–Q7.
- **README health check**: issue DN procedure in the [README design specification](01_架构/README设计规范.md).
