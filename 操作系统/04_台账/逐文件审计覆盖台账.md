# File-by-File Audit Coverage

> Passing automated guards does not establish complete human reading. This records which files or scopes were checked, by which method, where the evidence is, and what remains. It does not replace `check-operating-system.ps1`.

## 1. Recording conventions

| Field | Meaning |
|---|---|
| File path / scope | Single file, directory, or explicit glob |
| Classification | Active / historical / mixed |
| Check method | Automated guard / read-only explorer / worker fix / main-session review |
| Coverage granularity | Full reading / sampling / pattern scan / link anchor / size check |
| Evidence | Agent ID, status line, handoff card, command, or guard name |
| Conclusion | Passed / fixed / false positive / awaiting review |

## 2. Coverage-type boundaries

| Type | Establishes | Does not establish |
|---|---|---|
| P4a-P4t automated guards | File existence, counts, links, anchors, some semantic patterns, hook runtime state, template cleanliness, offline borrowing-lifecycle consistency, and size boundaries | Correct semantics throughout every file |
| P4o active-Markdown scan | Relative links and anchors in active Markdown resolve | Every sentence in historical body text is current policy |
| Historical-boundary guard | Historical files open with a do-not-copy-and-execute / current-source notice | Historical body text needs no reading |
| Explorer full reading | Semantic issues found within the specified scope | Coverage outside that scope |
| 状态.md / CHANGELOG summary | What this round did | File-by-file evidence itself |

## 5. Rules for later entries

- Add a row for each deep audit. List individual files when possible; split a large scope into subledgers or state the sampling boundary.
- “Automated guards passed” establishes only their recorded coverage type; do not expand it into proof of complete human semantic review.
- If a later review truly reads every file in a directory, record the reviewer, time, finding IDs, resolutions, and verification commands.
