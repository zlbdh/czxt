# Long-Term Productization Roadmap

This records the stages for taking `czxt` from a local operating-system template to a productized template. It provides roadmap and acceptance criteria; it does not replace `README.md`.

## Stage definitions

| Stage | Name | Entry criteria | Exclusions |
|---|---|---|---|
| P0 | Organize the local template | Project area, project configuration, and template-root health checks pass | No publication or npm |
| P1 | Initial czxt publication | First commit pushed to zlbdh/czxt; remote main can be fetched | No installer commitment |
| P2 | Multi-project trials | At least two project cards pass trial installation with `实例化项目.ps1` and health checks | No project code in the template |
| P3 | Initial installer | Project cards drive instantiation with dry-run / apply | No npm registry publication |
| P4 | Package / CLI assessment | Stable installer, clear version strategy and rollback path | No packaging solely for appearance |

## Recorded acceptance

P1 is complete. Historical acceptance evidence includes:

- The template repository has its initial commit and remote-publication record.
- `项目区/本地实例/` is ignored; real projects stay outside the template repository.
- `项目配置/` contains only `_模板.project.json`, with no concrete project cards.
- `README.md` states that this is currently neither an npm package, an installer, nor a CLI.

P2 is incomplete; only initial self-hosting evidence exists. Completion still requires:

- At least two independent project cards passing separate `实例化项目.ps1` trials.
- Both project instances passing framework health checks with reviewable evidence.
- Sanitized registration results reflected in `项目区/清单.md`. Real project cards and business code still stay outside the template repository.

## Principles for later work

- Stabilize template structure before considering an installer.
- Make PowerShell scripts work on a native Windows machine before assessing cross-platform packaging.
- Register project instances through explicit project cards; do not infer projects by implicit scanning.
- The czxt repository contains the template itself, rules, capability assets, and sanitized examples. It does not contain concrete project cards, business code, secrets, APKs, or user data.
