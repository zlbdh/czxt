## I. Findings — 4 Industry Benchmarks

### 1. BMAD Method (Highest Benchmark / 46.7K Stars / v6.6.0 / 2026-04-29)

**Core architecture**: 12+ specialized AI agents / two cores: Agentic Planning + Context-Engineered Development / 4-stage progressive context build

**12 agents**: Analyst / PM / Architect / Developer / SM (Scrum Master) / UX / QA + game dev/creative innovation and other extensions

**Key innovations**:
- **Scale-adaptive intelligence**: bug fix = lightweight workflow / enterprise platform = full ceremony (architecture review + sprint plan + cross-agent collaboration)
- **Verifiable artifact**: each agent must produce verifiable documents (PRD / architecture diagram / test plan / sprint story) — more than a chat response
- **Universal**: compatible with Claude / Cursor / Windsurf / Copilot (MIT open source)

### 2. Kiro (AWS / Amazon Bedrock)

**Core architecture**: Spec-driven development (specs = unit of work)

**3 steering files**:
- `product` — project purpose + key capabilities
- `structure` — organizational principles / tool abstraction patterns / error-handling standards
- `tech` — technology stack + development guide

**Key innovation**: **Hooks event-driven automation** — file save / PR open / repo event triggers automated tests / documentation updates / fixture regeneration / cascading spec changes

### 3. Claude Code Skills Architecture (Official Anthropic)

**Core architecture**: 4-layer document pyramid + Progressive Context Loading

| File | Purpose | Loading time |
|---|---|---|
| `CLAUDE.md` / `AGENTS.md` | Persistent project context | Automatically injected every session |
| `MEMORY.md` | Decision log / prevent session amnesia | Always / on-demand |
| `SKILL.md` | Domain-expertise playbook | **Conditional loading** (determined by YAML front matter of ~100 tokens) |
| Context.md | Live context fragments | On demand |

**Key innovation**: **Progressive Context Loading** — 30 skills × 100 tokens = 3K cost vs full load of 30K (**10x cost savings**)

### 4. Multi-Agent Orchestration: 4 Core Patterns

| Pattern | Purpose | Industry adoption |
|---|---|---|
| **Orchestrator-worker** | Main agent decomposes tasks + multiple workers execute + aggregate | Most widespread |
| Split-and-merge | Multiple parallel branches + merge | High |
| Planner-generator-evaluator | Plan → generate → evaluate loop | Medium |
| Consensus | Multi-agent voting / consensus | Low |

**Cost optimization**: **Model tiers** — cheap model triage + capable model for complex reasoning → 40-60% cost savings

## III. Improvement Proposals (Ranked by Value × ROI)

### 🔴 P0 — Improvement 1: Introduce SKILL.md Architecture + Progressive Context Loading

**Pain point**: all 7 files in PM工作区/项目PM-咪咪/速查表/ are fully grepped on every PM role switch (always-load) / currently 12.5KB / future expansion to 30+ quick references will balloon

**Upgrade direction**:
- 速查表/ → SKILL.md pattern (add YAML front matter to every file)
- Add Q4 “description-matched quick references” to PM role-switch Q1-Q3 → conditional loading
- 6 PM subroles × N quick references scales naturally

**Benefits**: 5-10x context savings / more precise triggers / unlimited growth in quick-reference count

**Difficulty**: M / **Recommend starting the Sprint-8 PROP-030 PRD**

### 🔴 P0 — Improvement 2: Hooks Event-Driven Trace Records (Addresses Repeated PM Self-Corrections #62/#57/#58)

**Pain point**: Issue AJ trace mechanism **failed 9 times** (PM self-corrections #38/#41/#42/#54/#55/#56/#57/#58/#62) — failure of “soft rules relying on PM diligence” demonstrated 9 times

**Upgrade direction (adopt the Kiro Hooks pattern)**:
- **Automatically trigger** after chat short-form output: scan PM transitions at the end of 状态.md / >5 minutes since the previous entry + framework changes → mandatory “add missing entry” prompt
- Do not depend on PM self-observation → hard mechanism constraint

**Benefit**: address the root cause in PM self-correction #58: “PM self-observation decay needs an external trigger”

**Difficulty**: H (requires Cowork / Codex hook-interface support / Issue CK upgrade PROP-027 v2)

### 🟡 P1 — Improvement 3: Standalone PM Self-Correction Artifacts

**Pain point**: 26 PM self-corrections #38-#63 scattered across 状态.md / RETRO — not independently searchable / not independently verifiable / must be aggregated again when drafting a RETRO

**Upgrade direction**:
- Create `PM工作区/项目PM-咪咪/PM自纠/` (planned in README but not implemented)
- One .md file for each PM self-correction (number + triggering scenario + root cause + defense mechanism + follow-up)
- Accumulate across Sprints + automatic RETRO aggregation

**Benefits**: independent search / verify / faster recognition of repeated patterns across Sprints

**Difficulty**: L / **Can execute immediately**

### 🟡 P1 — Improvement 4: Cross-PM Shared Skill Library

**Current state**: private quick references for each PM + cross-boundary prohibition / general SOPs (e.g. undo git changes / recover from Cowork mount stale) repeated across PMs
**Upgrade direction**: create `操作系统/02_智能体/共享技能/` — general SOPs across PMs (distinct from “private PM quick references”)
**Difficulty**: M

### 🟢 P2 — Improvement 5: Upgrade Scale-Adaptive Automatic Classification

**Current state**: PM subjectively assigns L1-L4 change levels
**Upgrade direction**: add Q4 “scale classification” to decision-checkpoint workflow → automatically select workflow path (bug = skip PRD / Sprint work segment = standard / architecture refactor = full ceremony)
**Difficulty**: M

### 🟢 P2 — Improvement 6: Model Tiers (40-60% Cost Savings)

**Current state**: business code + framework governance all use MiMo (mimo-v2.5-pro)
**Upgrade direction**: retain the model for business code (user conversations) / use a lightweight model for framework automation triggers
**Difficulty**: H / candidate issue backlog

## V. Key Insights

### 1. “{{PROJECT_NAME}}” Has Surpassed the Industry Average

Compared with BMAD (the strongest industry benchmark):
- ✅ Agent count / document layers / decision records / Scale-adaptive — **aligned**
- ⚠️ Skills architecture / Hooks / PM self-correction artifacts — **3 clear areas for upgrades**

### 2. Accumulated PM Self-Corrections Are the Real Moat

26 PM self-corrections (#38-#63) show the “operating system” continuously healing itself — the industry (BMAD/Kiro) has **no equivalent mechanism**.

### 3. The Real Cause of Issue AJ Trace Collapse Is “Soft-Rule Failure”

9 instances of the same pattern: PM self-observation rules are ineffective → **hard Hooks mechanism constraints are mandatory** (Improvement 2).

### 4. Cross-Tool AGENTS.md Standardization Is the 2026 Consensus

Cursor / Claude Code / Cline / Roo Code / Codex all support it — {{PROJECT_NAME}} already has AGENTS.md ✅
