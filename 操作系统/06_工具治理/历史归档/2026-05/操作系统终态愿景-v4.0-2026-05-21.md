## ⭐ Core Design Philosophy (PM Self-Corrections #64 + #67-#72 Accumulated / 2026-05-22)

### Philosophy 1: Fully Decouple PM Roles from Tool Carriers (PM Self-Correction #64)
- PM role = abstract collaboration role
- Tool = replaceable carrier (Cowork / Cursor / Cline / Codex and others are all carriers)

### Philosophy 2: 9 PMs, 4 Categories + Main-Meta-Sub-Subsub Four-Layer Nesting (PM Self-Corrections #68 + #72 / 2026-05-22 Upgrade)

⭐ **PM self-correction #72**: The Knowledge PM **is not a subsub PM** — it handles **consolidation for the entire project** (across the complete lifecycle + coordination across 9 PMs) / promoted to **meta-layer PM** (close to the main PM / independent meta-decision layer)

- **Main PM** (1 / sole external identity): Project PM “Mimi”
- **⭐ Meta-layer PM** (1 / across the entire project / close to the main PM): 🪞 Knowledge PM “Curator”
- **Sub-PM decision layer** (5 / orchestrates without hands-on work): Operating System / Product / Technical / Test / Operations
- **Subsub-PM implementation layer** (2 / dispatched across PMs): 🔨 Development PM “Implementer” + ✅ Test and Release PM “Closer”

### Philosophy 3: Three-Layer Consolidation Architecture (PM Self-Corrections #69 + #71)
- **Layer 1**: private consolidation by each PM (PM autonomy)
- **Layer 2**: central consolidation by the Knowledge PM (coordination across 9 PMs + meta-layer responsibilities)
- **⭐ Layer 3**: project consolidation (entire project lifecycle / business + product + users + market)

### Philosophy 4: Dual-Layer Validation Architecture (PM Self-Correction #70)
- **Layer 1**: private validation dimensions for each PM (each PM validates itself + downstream work)
- **Layer 2**: central validation by Test and Release PM (cross-PM coordination + end-to-end business validation)

### Philosophy 5: Entire Project Lifecycle Scope (zlbdh Screenshot Annotations)
- **More than development** — covers initiation + requirements + design + development + testing + release + operations + promotion + data feedback + evolution

## IV. ⭐ Meta-Rule Pool Explained (Answer to zlbdh L150)

### What Is the Meta-Rule Pool?

**Meta-rule pool** = the project’s **permanent mandatory collaboration rules** — analogous to a national constitution vs ordinary laws:
- Ordinary rules = routine PROP / Sprint decisions / handoff cards (can be changed or abolished)
- **Meta-rules** = permanently current, highest-level mandatory collaboration rules (mandatory across Sprints / not readily overturned)

### Promotion Path

```
PM self-correction (field lessons)
     ↓ Accumulate 3+ occurrences of the same pattern
Candidate meta-rule (issue alphabet A-CQ+)
     ↓ Sprint RETRO evaluation
Draft PROP
     ↓ zlbdh approve
ADR (permanent record)
     ↓ Write into the meta-rule pool
✅ Permanent meta-rule (mandatory / across Sprints / across PMs / across tools)
```
