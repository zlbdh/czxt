## I. 5 Major Industry SOTA Memory Architectures (2026)

### 1. Mem0 (Strongest / 47K Stars / Recommended)

**Architecture**:
- **3-tier scope**: user (long-term user-level) / session (session-level) / agent (agent-level)
- **Hybrid storage**: vector + graph + key-value
- **Automatic memory extraction**: automatically extract facts / relationships / preferences from conversations
- **CRUD API**: external memory service (called by agents)
- **47K+ GitHub stars** (largest community)

**Characteristics**:
- The agent does not reason about memory itself (opposite to Letta)
- Suits most teams / strongest general-purpose option

### 2. Letta (Formerly MemGPT / Self-Managing)

**Architecture**:
- The agent reasons about memory **within its own loop**
- Long-term memory paging (short-term context + persistent long-term layer)
- Built-in memory hygiene mechanism

**Compared with Mem0**:
- Mem0 = memory as service (external CRUD)
- Letta = memory in agent (agent autonomy)
- **Opposing design philosophies**

### 3. LangMem (Native to LangChain / LangGraph)

**Architecture**:
- Official LangChain memory SDK
- Supports **3 memory categories** (episodic / semantic / procedural)
- Integrates fact extraction + behavior-level memory
- Native LangGraph support

### 4. Provider-Managed (ChatGPT Memory / Claude Projects)

**Architecture**:
- Provider-built memory service
- Users need not build their own
- Simple, but locks users to the provider

### 5. Custom In-App Schema (DIY)

**Architecture**:
- Project-defined memory schema
- Full control / high maintenance cost
- **{{PROJECT_NAME}} currently belongs to this category**

## II. 3-Category Memory Taxonomy (Industry Consensus / Lessons from Cognitive Science)

In 2025-2026, the industry converged on a **3-tier taxonomy** (based on 50 years of cognitive-science research):

### Episodic Memory
- **What**: historical events / user-interaction records / timestamped “what was done”
- **Industry examples**: ChatGPT conversation history / Mem0 session memory
- **Current operating system**: 状态.md + 状态-archive/ + version timeline + PM self-correction artifacts + 交接区/

### Semantic Memory
- **What**: facts / concepts / rules / stable “what is known”
- **Industry examples**: Mem0 user memory / LangMem fact extraction
- **Current operating system**: 05_记忆/INDEX.md + 议题全景.md + ADR / RETRO + 能力资产/rules + shared/

### Procedural Memory
- **What**: how-to / workflows / SOPs / “how to do it”
- **Industry example**: LangMem behavior memory
- **Current operating system**: 6 PM quick-reference sets (SKILL.md) + 共享技能/ + decision-checkpoint workflow

## V. 5 Major Improvement Proposals (Ranked by ROI)

### 🔴 P0 Improvement 1: Automatic Memory Extraction (Led by the Self-Healing PM)

**Current state**: PM self-corrections / issues / RETRO are all written manually

**Upgrade**:
- Self-Healing PM “Reflector” (added by PM self-correction #65) proactively scans sessions to extract candidate memories
- Automatically generate PM self-correction artifact drafts (implement after PM review and approval)
- Automatically classify into 3 categories (episodic / semantic / procedural)

**Benefit**: truly eliminate Issue AJ trace collapse at its root (mechanism-level solution)

**Difficulty**: M / after the Self-Healing PM is implemented

### 🔴 P0 Improvement 2: Connect Vector Search (mem0 Integration)

**Current state**: locating PM self-corrections / issues / quick references relies entirely on grep + Read

**Upgrade**:
- Add embeddings to `操作系统/05_记忆/INDEX.md` + PM self-correction artifacts + Issue Panorama
- Introduce mem0 or LangMem SDK
- AI matches by description (replaces manual PM Q4 trigger matching)

**Benefit**: real 10x Progressive Context Loading savings (complete PROP-031)

**Difficulty**: H / requires SDK integration + complete Issue CO

### 🟡 P1 Improvement 3: Graph Memory Entity-Relationships

**Current state**: relationships among issues / PM self-corrections are implicit / meta-rule promotion paths are manual

**Upgrade**:
- Explicitly model entity-relationships (issue ←→ PM self-correction ←→ ADR ←→ meta-rule pool)
- Graph database (Neo4j / or lightweight .json schema)
- AI reasons about questions such as “Which PM self-correction links to ADR-N?”

**Benefit**: automatically identify repeated patterns across Sprints (Self-Healing PM upgrade)

**Difficulty**: H / Issue CV candidate

### 🟡 P1 Improvement 4: Multiple Forms of Automation Triggers (Broader Hooks)

**Current state**: semiautomatic PowerShell check-pm-tracking.ps1

**Upgrade** (zlbdh reminder, rendered in English: “Hooks are only one form”):
- file watch (fs events / watchman)
- cron schedule (scheduled checks)
- MCP tool events (mcp__scheduled-tasks)
- Existing Codex/Claude hooks (different forms across tools)
- Chat output events

**Benefit**: real Issue AJ trace automation (complete Layer 4)

**Difficulty**: M / Sprint-9 when tool capabilities are ready

### 🟢 P2 Improvement 5: Make 4-Tier Memory Scope Explicit

**Current state**: 4 tiers (Global / Project / Agent / Session) already exist in practice / not explicitly labeled

**Upgrade**:
- Add YAML frontmatter `scope: global/project/agent/session` to every memory file
- Classify INDEX by scope
