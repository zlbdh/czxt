# Workflow: Approval and Archival

These rules cover each transition from a pending proposal (PROP) to final archival. When zlbdh signals a decision, Project PM first runs Q1-Q7, then routes by path to Product PM, Operating System PM, or Test and Release PM. Tools are execution runtimes. **Do not rely on memory.**

## Signals and required actions

### A. Approval

**Approval signals from zlbdh:** agreement, approval, “OK, go ahead,” “you may do it,” or “✓”.

**Project PM orchestrates these steps in order:**

1. **Update the PROP header status:**
   ```
   - **Status**: Approved · Open / Pending scheduling (from YYYY-MM-DD; ADR-XXX still to be written)
   ```
   Use today's date; look up the ADR number in section C. The substatus may later become “Pending rereview,” “External capability tracking,” or “Pending reassessment.” The primary state must remain `Approved · Open`.

2. **Move the file:**
   ```
   确认改动/待审批/PROP-XXX-...md
       → 确认改动/已审批/进行中/PROP-XXX-...md
   ```

3. **Update counts in `确认改动/README.md`:** pending approval −1; in progress +1; add the item to the in-progress list.

4. **Required for L3/L4: route to Product PM to create the PRD entry.** Add F-XXX in `Docs/1-需求文档/Sprint-N需求清单.md`; see section C for ID lookup. Without it, Development PM “Implementer” cannot find the feature ID during implementation.

5. **Required for L4: route to Operating System PM to reserve the ADR.** Create a placeholder at `Docs/3-开发文档/adr/ADR-XXX-...md` to prevent later ID collisions. Include at least `# ADR-XXX · <Title>` and `Status: Draft`.

### B. Rejection

**Rejection signals from zlbdh:** “do not do it,” “rejected,” “pass,” “leave it for now” when this clearly declines the proposal, or “✗”.

**Project PM orchestrates:**

1. **Update the PROP header status:**
   ```
   - **Status**: Rejected (YYYY-MM-DD; reason: ...)
   ```
   Record zlbdh's stated reason. If the user only says “do not do it” without explaining, ask for the reason before recording it.

2. **Move the file:**
   ```
   确认改动/待审批/PROP-XXX-...md
       → 确认改动/拒绝/PROP-XXX-...md
   ```

3. **Update README counts:** pending approval −1; rejected +1.

**Do not use `rm`.** Archive rejected proposals so the reason remains available even six months later.

### C. ID lookup — required before writing a new PROP / ADR / RETRO

**Do not guess IDs from memory.** PROP-002 and ADR-005 collided in the recorded incident.

```powershell
# Find the current highest PROP ID
Get-ChildItem -Path '确认改动' -Recurse -Filter 'PROP-*.md' -File |
  Select-Object -ExpandProperty BaseName |
  Sort-Object -Unique

# Find the current highest ADR ID
Get-ChildItem -Path 'Docs/3-开发文档/adr' -Filter 'ADR-*.md' -File |
  Select-Object -ExpandProperty BaseName |
  Sort-Object

# Find the current highest RETRO ID
Get-ChildItem -Path 'Docs/7-复盘' -Filter 'RETRO-*.md' -File |
  Select-Object -ExpandProperty BaseName |
  Sort-Object
```

New ID = highest ID in the output + 1.

### D. Implementation complete

See [Implementation DoD](实施循环-DoD.md). Its PROP archival step updates the status to completed, moves the file from `进行中/` to `已完成/`, and updates README counts.

### E. Abandonment during implementation

**Trigger:** zlbdh says during implementation that the work is no longer wanted, or that the approach is wrong and should be rolled back.

**Project PM orchestrates:**

1. **Update the PROP header status:**
   ```
   - **Status**: Approved · Abandoned (abandoned YYYY-MM-DD; reason: ...)
   ```

2. **Move the file:**
   ```
   确认改动/已审批/进行中/PROP-XXX-...md
       → 确认改动/已审批/已弃用/PROP-XXX-...md
   ```

3. **Update README counts:** in progress −1; abandoned +1.
4. **Code:** if some code has already changed, create a rollback proposal (PROP-YYY), obtain approval through section A, and only then change the code.
5. **PRD:** mark the corresponding F-XXX in the Sprint list as `Abandoned (reason: ...)`; do not delete the entry.

## Quick reference

| User signal | File route | Header status |
|---|---|---|
| Agreement / “OK, go ahead” | 待审批 → 已审批/进行中 | Approved · Open / Pending scheduling (date + ADR-XXX pending) |
| “Do not do it” / rejection | 待审批 → 拒绝 | Rejected (date + reason) |
| All DoD checks pass | 进行中 → 已完成 | Approved · Completed (date + ADR-XXX) |
| “Wrong approach; roll back” | 进行中 → 已弃用 | Approved · Abandoned (date + reason) |

## Principles

- **Status and path always agree.** Changing one requires changing the other.
- **Do not delete PROPs.** Keep rejected and abandoned proposals in the archive.
- **List existing IDs before assigning a new one.**
