# Workflow: Requirement Intake

When zlbdh sends a new requirement, Mimi follows this process.

## Step 1: Classify

Determine the size of the request:

```text
Single label / color / small single-file change → Small: enter the Development PM implementation loop.
New feature / module / multiple files / data schema change → Large: first draft a PROP in 确认改动/待审批/.
Unclear → Ask zlbdh 1–3 clarifying questions using the current runtime's available tools.
```

## Step 2: Confirm understanding

Restate the requirement to yourself in one sentence. If you cannot state it clearly, you have not understood it.

Example:
- zlbdh: “Can the accounting list have a calendar view?”
- Restatement: “Add a monthly calendar to the accounting page; selecting a day opens its details.” ✓

## Step 3: Check clarity

Five required questions:
1. Which feature is this?
2. How does the data change?
3. Where is the UI entry point?
4. How are edge cases handled: no data, errors, and loading?
5. Is it P0, P1, or P2?

For any unknown answer, ask zlbdh immediately. Do not guess.

## Step 4: Record the requirement

Choose the record by size:

- **Large / L3–L4 change**: first write `确认改动/待审批/PROP-XXX-...md` and wait for zlbdh's approval. After approval, proceed to PRD/ADR through [approval and archival](审批与归档.md).
- **Small or already approved requirement**: use the appropriate Sprint file in `Docs/1-需求文档/`. Write the user story, acceptance criteria, effort estimate, and affected files in business terms.

Rule: a large change outside the `确认改动/` lifecycle must not go directly into `Docs/1-需求文档/`.

## Step 5: Let zlbdh review

For a large change, show or link the PROP draft and wait for explicit approval.

For a small change, say, “I will handle this directly and report when it is done.”

## Step 6: Add tasks

Use the current runtime's available planning or task records to write the breakdown, with one task per step.

## Step 7: Hand off to the Development PM

Switch to the Development PM “Implementer” or its execution runtime. Follow `操作系统/02_智能体/开发PM-实施者.md` and `能力资产/rules/写代码.md`.

## Complete example

zlbdh: “**Could Home have a one-sentence daily reflection that AI summarizes on the weekend?**”

Mimi:

1. **Classify**: new feature plus data schema change → **large change**.
2. **Restate**: write one sentence on Home each day, save it, and let AI compile a weekend review.
3. **Check clarity**:
   - Feature: Home, data, and AI ✓
   - Data: new table or merge into `chatMessages`? ❓
   - UI: where on Home? ❓
   - Edge case: what happens on the weekend if no reflections were entered? ❓
   - Priority: to be decided by the user ❓
4. **Ask four clarifying questions**:
   - How long should reflections be saved: permanently or 30 days?
   - Where on Home: above Chat, below Habits, or a separate card?
   - How should AI handle missing days: skip or remind?
   - Is this more urgent than Sprint 1's eight requirements?
5. **After receiving answers**, first write a PROP in `确认改动/待审批/`.
6. **Break down tasks** and list code changes.
7. **Wait for zlbdh's approval**.
8. **After approval**, create the PRD/ADR through [approval and archival](审批与归档.md), then hand implementation to the Development PM “Implementer.”
