## One sentence

Clarify the template/history boundary for outdated source-project material presented as current template facts, and fix temporary-directory leaks that remained after passing hooks-smoke tests.

## Background and motivation

- The root README still described a pre-first-commit state, although P1 was complete and P2 had only initial self-hosting evidence.
- `操作系统/00_总入口.md` called all 38 ADRs permanently current, contradicting the index's 35 current and three superseded records.
- Project structure, technology stack, API, and database-schema documentation under `Docs/3-开发文档/` presented source-project business details as current template facts.
- The dependency matrix and brand dictionary contained fixed dependencies, models, and endpoints unsuitable for arbitrary project instances.
- `hooks-smoke-claude-contracts.ps1` created %TEMP% fixtures without cleanup. The reproduction exited 0 while the directory count rose from 9 to 10.
- P4s scanned only a few source-project names and could not prevent this semantic drift.

## Proposed approach

1. Correct README, roadmap, and ADR-count descriptions.
2. Make current project structure a neutral template-root/project-instance guide. Mark the source technology stack, API, and schema as historical references or provide fill-in templates.
3. Make the dependency matrix and brand dictionary generic templates driven by project cards and repository facts.
4. State in current PM playbooks that concrete paths, commands, and artifacts come from project-instance facts, without changing the nine PM responsibility boundaries.
5. Add targeted current-truth assertions to P4s with RED/GREEN evidence.
6. Add leak regression assertions and `try/finally` cleanup for Claude hook fixtures with RED/GREEN evidence.

## Estimated impact and cost

- Effort: M.
- Affected files: 36, comprising 32 modifications and four additions, including guards, retrospective, CHANGELOG partitioning, single-source records, and handoff.
- Risks: accidentally deleting historical text, broadening playbook responsibilities, or applying current-truth guards to historical ADRs/RETROs.
- Schema change: No.

## Alternatives

- Correct only four visible text issues. Rejected because source-project drift and smoke leaks could recur.
- Abstract all technology stacks and release roles across platforms. This would change role boundaries and meta-rules and requires a separate L4 proposal.

## Likely reasons for rejection

The scope is broad, and retaining source-project material may be preferred. To reduce risk, preserve historical evidence, correct only claims of current truth, and add targeted regression gates.
