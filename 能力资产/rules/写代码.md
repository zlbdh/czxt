# Rule: Writing Code

Use with Development PM “Implementer.” These are detailed styles, patterns, and antipatterns. The current source is `能力资产/rules/写代码.md`; do not use the former `能力资产/skills/写代码.md` path.

## File size guidance (PROP-013 / ADR-017)

| Tool | Threshold | Response |
|---|---|---|
| **Cowork** (mount truncation risk) | 6,500-byte advisory | Above 6,500 bytes, **write large files with Python/Bash**, bypassing Edit. Health checks warn but do not require splitting. |
| **Claude Code / Codex** (local) | **No hard limit** | Use engineering judgment. |
| **All tools** | 8 KB extraction advisory | Above 8 KB, consider splitting by responsibility, independently of tool capabilities. |

Historical rationale:

- PROP-007 P1-3 / ADR-010 originally required splitting at 6,500 bytes, providing a safety margin below Cowork's 9 KB mount truncation limit.
- Applying that limit to Claude Code / Codex unnecessarily restricted tools without that mount limitation.
- RETRO-005 cards 2/3 recorded repeated false warnings from cached mount `wc -c` output and unnecessary component extraction.
- PROP-013 / ADR-017 introduced tool-specific guidance.

Scope remains unchanged:

- Applies to `{{APP_REPO_DIR}}/src/`, `操作系统/`, and `能力资产/`.
- Excludes `Docs/`, `确认改动/已审批/已完成/`, `交接区/已接手/`, and `交接区/历史归档/`: infrequent writes and historical archives.

See dimension 1 of the [project health check](../skills/项目体检.md) for the current warning list.

## Naming

| Element | Style | Example |
|---|---|---|
| React component | PascalCase | `TaskDetailModal` |
| React file | PascalCase.jsx | `Health.jsx` |
| Utility function | camelCase | `parseLedgerText` |
| Utility file | camelCase.js | `ledger.js` |
| Test | xxx.test.js | `ledger.test.js` |
| Constant | SCREAMING | `LLM_DEFAULTS` |
| State hook | use prefix | `useAppData` |

## File organization

- Organize shared UI by responsibility in `src/shared/`: basic structure in `components.jsx`; separate small files for buttons, inputs, statistics, calendars, and dialogs.
- Separate shared utilities **by function**: ai / health / ledger / date / image / devices.
- The main feature component, `<FeatureName>.jsx`, handles composition, state, and handlers. Extract child UI above the safe range into small files in the same directory.

## State management

- Global state has one source: `useAppData()`.
- Do not call `db.xxx` directly in components.
- Local UI state uses `useState`.
- Derived data uses `useMemo`.

## Data flow

User action → `actions.xxx()` → `db.xxx` → `setData` → re-render.

Do not:

- Call `setData` without writing to the database.
- Call `db.xxx` without updating `setData`.
- Use `await db.xxx` in a component.

## Error handling pattern

```jsx
const [error, setError] = useState('');

async function submit() {
  setError('');
  try {
    await actions.addRecord(...);
  } catch (e) {
    console.warn('submit failed', e?.message?.slice(0, 120));
    setError('The operation failed. Please try again.');
  }
}

// UI
{error && <div className="...">{error}</div>}
```

## AI call pattern

```jsx
const [loading, setLoading] = useState(false);

async function fn() {
  setLoading(true);
  try {
    const result = await callAI({ ... });
    // Use the result.
  } catch (e) {
    // Show a helpful error.
    console.warn('ai call failed', e?.message?.slice(0, 120));
    setSomething('AI is temporarily unavailable. Please try again later.');
  } finally {
    setLoading(false);
  }
}
```

## React practices

- Default-export pages: `export default function HomePage`.
- Use named exports for shared components: `export function Card`.
- Use `useMemo` for derived data; avoid repeated computation.
- Use `useRef`, not `document.querySelector`, for references.
- Put side effects in `useEffect`, not rendering.

## Antipatterns to avoid

- `setInterval` in a component without cleanup.
- Async operations without try/catch.
- Directly mutating props.
- Using an index as a key.
- Large inline style objects: use `className` above five properties.
- Keeping multiple responsibilities in one file. Split by responsibility; 200 lines is a style reminder, not a hard gate.
- Calling setState in useEffect without dependencies.

## Code style

- Indent with two spaces.
- Use single-quoted strings.
- End statements with semicolons for safety.
- Name functions for their action: `parseLedgerText` is clearer than `process`.
- Comments explain why; the code already explains what.

## Checklist after each file change

- [ ] Does file size trigger the tool's advisory? Use Python/Bash for Cowork writes above 6,500 bytes; consider splitting responsibilities above 8 KB for all tools.
- [ ] Is the ending complete? Verify large writes with Read / tail.
- [ ] Were tests added?
- [ ] Did esbuild syntax checking pass?
- [ ] If business behavior is affected, was CHANGELOG updated?
