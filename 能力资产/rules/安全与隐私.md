# Rule: Security and Privacy

Current rules for privacy, credentials, and data protection. Class C boundaries in the [three-class behavior rules](../../操作系统/01_架构/三类行为铁律.md) are the highest gate. This file specifies default actions for sensitive areas.

## Default actions

- API keys and tokens: never put them in tracked Git files, handoff cards, or external services. Nonsecret baseUrl/model defaults may be maintained in code under ADR-022 safeguards. Handle `.env.local` only under the Class B safeguards in the three-class rules.
- User data: even default read-only access to IndexedDB, backup JSON, or device data requires care. Deletion, external transmission, upload, and migration fall under Class C; stop and wait for zlbdh's explicit authorization. The authoritative Class C restrictions still apply.
- Backup export: JSON may contain chatMessages, tasks, health/profile, or other information. Explain the risk before generating or processing it; keep output paths and content scope traceable.
- logcat and screenshots: check for keys, phone numbers, accounts, private chats, health data, and personal information in paths before sharing.
- Cloud sync and third-party integrations: disabled by default. Propose a PROP/ADR before first adding cloud sync, external analytics, or an app-store privacy policy for publication.

## Current baseline

- API keys never enter Git.
- A personal-use app stays local by default; all data remains on the device.
- Users keep their own exported JSON backups.
- AI does not proactively read, store, or externally transmit user data. Explicitly provided excerpts are used only for the current task.

Escalate higher-risk situations into dedicated rules or a PROP/ADR using the triggers below.

## Escalation triggers

Any one of these requires an immediate PROP and more complete dedicated rules:

- A real API key or private token is about to enter Git, including token-plan-* tokens or Anthropic keys in any committed file.
- AI first intends to read, modify, or back up the user's IndexedDB data.
- zlbdh first shares backup JSON with another person or third party.
- First proposed cloud sync, departing from the original local personal-use model.
- Preparation for Google Play or another app store, which requires a privacy policy.

Do not postpone escalation when any of these five conditions applies.

## Accidental deletion recovery (PROP-007 P1-4)

AI must not delete files in violation of Class C. If an accidental deletion occurs:

### Immediate response

1. **Stop.** Perform no further Write/Edit operations that could overwrite more data.
2. **Tell zlbdh.** State which file was deleted, why, and its last observed approximate byte length.
3. **Do not recreate it from memory.** Reconstructing the wrong version can be worse than the loss.

### Recovery options for zlbdh, in priority order

1. Previously committed file: run `git restore <file>` on Windows.
2. Uncommitted file still in the sandbox: try the Read tool; the mount cache may retain a copy.
3. `状态.md`, PROP, or ADR: recover from prior conversation or screenshots if available.
4. Code: AI may reconstruct from memory **only with a diff presented to zlbdh for confirmation**.

### Prevention

- AI **never proactively deletes files**; replace content using Edit instead.
- Obtain explicit confirmation from zlbdh before deleting a file, using the current environment's available confirmation mechanism.
- Deletion authorization applies only to the explicitly identified, non-Class-C target in that instance. Never generalize it into standing authorization or use it to bypass the three-class rules.
