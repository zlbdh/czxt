# Rule: Known Technical Constraints (12-Item Quick Reference)

These are recurring project pitfalls. Start here; symptoms, historical examples, and command templates are in the [appendix](已知技术约束-附录.md).

## Remember these four rules first

1. **Check P4b before editing large files.** Be careful near 6500B; consider splitting files at >=8000B. When a large-file edit is necessary, read back its size and tail afterward.
2. **Use local Windows `build-apk.ps1` as the primary APK path, with manually triggered GitHub Actions as the fallback.** Sandboxes usually lack the required Android SDK, network access, or JDK. A sandbox's inability to build an APK is not an application failure. The Test and Release PM handles packaging within the release completion permissions.
3. **Pin Android/Capacitor builds to JDK 17.** Do not run Gradle directly with JDK 21+.
4. **Guard native commands in Windows PowerShell against shim and stderr errors.** Prefer `npm.cmd` or `cmd /c "npm ..."` in scripts. When capturing stderr, determine success from `$LASTEXITCODE`.

## All 12 constraints

| # | Constraint | Trigger | Required action |
|---|---|---|---|
| 1 | Mount writes can truncate large files | Editing large files in `操作系统/`, `能力资产/`, or `{{APP_REPO_DIR}}/src/` | Check P4b first; be careful above 6500B and prefer splitting at >=8000B; read back size and tail |
| 2 | Sandboxes lack the Android SDK and access to Google/Gradle sources | APK packaging or Gradle builds | Use the Windows host; run code checks, vitest, and vite build in the sandbox |
| 3 | Sandbox `npm install` is slow | First dependency installation | Use `--no-audit --no-fund --silent`, retry failures, and use `--prefer-offline` when needed |
| 4 | Sandbox restarts clear `/tmp` | Temporary build or test directories | Do not rely on `/tmp` for persistence; copy artifacts back to a project path |
| 5 | Capacitor + Android requires JDK 17 | `gradlew assembleDebug` | Point `JAVA_HOME` to Eclipse Temurin 17, not the newest JDK |
| 6 | `ANDROID_HOME` must be set | Android builds | Set `%LOCALAPPDATA%\Android\Sdk` or write `android/local.properties` |
| 7 | `node_modules` is platform-specific | Running Windows dependencies in a Linux sandbox | Install Linux dependencies in the sandbox; do not reuse Windows `node_modules` |
| 8 | `window.storage` is only a compatibility layer | Migrating old v1 or Claude Artifact code | Use the shim for legacy code; use Dexie/IndexedDB directly in new code |
| 9 | CSS `@import` must appear at the top | Editing fonts in `src/index.css` | Put `@import` on line 1, before `@tailwind` |
| 10 | localStorage has a quota of about 5MB | Chat history, backups, or large datasets | Put large datasets in IndexedDB; reserve localStorage for small configuration values |
| 11 | The PowerShell `npm.ps1` shim can misalign arguments | Running npm subcommands in scripts | Use `npm.cmd` or `cmd /c "npm <subcommand>"` |
| 12 | PS5.1 `2>&1` with EAP=Stop can terminate prematurely | Capturing native-command stderr | Temporarily set `$ErrorActionPreference="Continue"`, then check `$LASTEXITCODE` |

## Current large-file write policy

| Tool or context | Threshold | Action |
|---|---|---|
| Cowork / mount truncation risk | 6500B soft warning; historical hard truncation around 9KB | Write with a script or split the file; read back and verify afterward |
| Claude Code / Codex | 8000B engineering recommendation | Prefer an entry document plus appendix; never discard contracts just to reduce bytes |
| All tools | Before a critical judgment | Trust `check-operating-system.ps1`, P4b, and a Read verification; do not rely on `wc -c` alone |

## Safe PowerShell native-command template

```powershell
$prevEAP = $ErrorActionPreference
$ErrorActionPreference = "Continue"
try {
  $output = & $cmd @args 2>&1
  $code = $LASTEXITCODE
} finally {
  $ErrorActionPreference = $prevEAP
}
if ($code -ne 0) { throw "failed ($code): $output" }
```
