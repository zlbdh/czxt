# Skill: Borrowing · Command Appendix

Use this appendix only to call the tested facade from the [borrowing skill](借鉴.md); it does not define a second operating workflow. The [borrowing governance rules](../rules/借鉴治理.md) are the sole authority for allowed permission values, defaults, and behavior classification.

## Usage boundaries

Capture enters same-volume `staging` first and is promoted atomically only after the candidate passes validation. The executor runs `P4t` before and after promotion; `P4t` always remains offline. Operators must not manually assemble underlying Git, copy, or hash commands, or add internal execution injection parameters to the public entry point.

### Fixed v1 resource limits

|Resource|Fixed limit|Exact boundary|
|---|---:|---|
|leaf|10000|10000 is valid; 10001 fails|
|Total bytes|536870912|536870912 is valid; 536870913 fails|
|Bytes per item|67108864|67108864 is valid; 67108865 fails|

|Metadata bytes|65536|65536 is valid; 65537 fails|
|redirect|10|10 is valid; 11 fails|
|Git timeout|300000ms|300000ms is valid; 300001ms fails|
|P4t timeout|120000ms|120000ms is valid; 120001ms fails|

All limits are fixed and cannot be overridden. P4t timeout uses reason_code=p4t-process-failed; every other resource limit violation uses reason_code=resource-limit.

The transaction tree seal separately allows at most `20000` directory/file members and reuses the `536870912` total-byte limit. It stops early during per-member DFS and streams SHA-256 with a 1 MiB buffer, without retaining an entire tree or file in memory at once.

## Close an item

Before closing, follow [borrowing governance](../rules/借鉴治理.md) to generate `borrowing-evidence/v1` binding time, command, exit, and the target-manifest digest. Then record implementation targets, adaptation differences, implementation records, and machine-format fresh evidence in the active card while it remains `verifying`. For reject, complete assessment evidence and rejection reasons in `assessing`. Then call only the trusted close entry point:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\能力资产\tools\scripts\close-borrowing-item.ps1 `
  -Root $PWD.Path `
  -CardPath '.\借鉴区\事项\<borrow_id>\借鉴卡.md' `
  -ClosedAt '<ISO 8601>' `
  -Reason '<closing reason>' `
  -Confirmation '<auditable confirmer>'
```

The entry point places the original active card and closed candidate in `.staging-close-<32hex>/` under the item's parent directory. It installs the candidate with a no-overwrite move, calls the seal helper, and uses the full root P4t as the final gate. Neither candidate installation nor seal commit may overwrite later objects. After P4t exit 0, it must still lock the formal card, verify identity and sealed bytes, and clean up this transaction's owned staging while holding the lock before succeeding. Restore the original active card and retain the failed candidate at `.staging-close-<32hex>/借鉴卡.md` only when ownership is provable and `content-deleted` has not been reached. If the first formal-card snapshot after seal exit 0, attestation parsing, or its identity/length/SHA-256 binding fails, report exactly `stage=seal / reason_code=seal-ownership-unproven` and preserve the current formal card and staging. If the materials prove binding to the current formal object but `borrow_id` differs, ownership remains provable, and the original active card can be safely restored from the full snapshot. Failures after the irreversible `content-deleted` completion point must not roll back the formal card. Every branch outputs actual normalized paths; never manually invoke seal as a replacement for the close transaction.

Optional path output must use an explicit state object with a writable `Value` property, not optional `[ref]` parameters. The executor computes the attempted path and writes it to the state object before creating the staging directory. This lets it report the path actually attempted even if creation or compensation fails, while zero-write preflight still outputs `none(not-created)`.

The staging ownership chain is fixed: atomically create the staging directory relative to the trusted parent directory handle; create the first `原活动卡.bin` using directory-handle-relative CreateNew, then write, flush, and bind through that same handle. Keep its file lease for the entire transaction so the directory remains nonempty. Create candidate `借鉴卡.md` with directory-handle-relative CreateNew as well.

The cleanup order is fixed: `Candidate→retained Original→content-deleted→directory`. Open Candidate once through its bound handle, validate it, and set delete-pending on that same handle. Set delete-pending for retained Original through the same handle held by its retained lease. Immediately enter `content-deleted`, then delete the directory through its original creation handle. Leave no window between validation and opening a path; on creation failure, delete only objects bound to this transaction's handles.

After P4t exit 0, acquire the formal card's final lock with one OPEN_REPARSE_POINT open and verify canonical path, regular non-reparse type, link count=1, identity, length, and bytes through the same handle. Hold this exclusive lease until staging cleanup ends. Never perform a separate safe-path check followed by reopening the path.

After seal, staging candidate updates follow a two-state contract: the formal-card ownership snapshot and current staging-candidate snapshot are independent states that rollback must validate separately. Do not prematurely change the expected staging contents to sealed bytes. After the Set commit in `Set-BctCandidateBytes`, update the state object before any further verification that can fail, so exception branches observe the candidate actually committed.

## Failure recovery

Failure output must identify the failed stage and `staging path`. After correcting authorization, input, or environment issues, retry through the main skill. A failure must not produce ready, manually promote incomplete output, overwrite an old capture, or silently delete user data.

For zero-write preflight failures, the fixed staging output is `none(not-created)`.
Output its normalized path only when staging already exists.
