# 技能：借鉴

本 Skill 是借鉴闭环唯一面向操作者的入口。判断边界以[借鉴治理规则](../rules/借鉴治理.md)为准，角色与状态流转以[借鉴完整工作流](../../操作系统/07_完整工作流/借鉴闭环.md)为准；受信任执行器的调用方式见[命令附录](借鉴-命令附录.md)。

## 触发与模式

请求出现“借鉴、参考、对标、吸收、学习其他项目、添加参考源、更新参考源、审计参考源”之一时，进入本 Skill。

模式只有四种：

- **接入**：冻结并登记一个来源版本。
- **评估**：比较现有能力，形成采纳结论。
- **落地**：把获批内容适配到目标责任路径并验证。
- **审计**：只读核对现有来源、事项和证据。

## 共同前置检查

先收口**目标问题**，再确认**来源**，最后明确**允许动作**；随后按 **A/B/C** 判断能否继续及是否需要另行确认。

必须从固定受信任路径 `能力资产/tools/scripts/check-os/framework-scope.ps1` dot-source 后调用 `Get-CzxtRootMode`；操作者不得替换加载路径。

**任何写入前**必须调用 `Get-CzxtRootMode`。函数返回 `project` 时映射为人类标签 `project-only`，只有此结果可以进入写入分支；返回 `template` 时映射为 `template-only`，只允许离线只读审计；`unknown`、`conflict` 对所有模式执行**零写入拒绝**。非 project 不得创建 `staging`、卡片或 `local state`。实现时比较函数实际返回值，不以人类标签代替返回值。

| RootMode | Skill 允许模式 | 写入边界 |
|---|---|---|
| project | 接入 / 评估 / 落地 / 审计 | 仅 project 可写 |
| template | 仅离线只读 P4t 审计 | 禁止写入 |
| unknown / conflict | 无 | 所有模式零写入硬失败 |

## 接入

接入仍仅允许 RootMode=project；template、unknown、conflict 必须前置拒绝。

1. 完成[共同前置检查](#共同前置检查)；`template-only / unknown / conflict` 一律前置拒绝。
2. 由 Skill 调用 `能力资产/tools/scripts/capture-borrowing-source.ps1`，操作者不拼接底层捕获步骤。
3. 读取执行器的 `P4t` 闸门结果；只有 `exit 0` 才输出 `ready`。

## 评估

1. 先盘点**当前已有能力**，避免把已存在能力重复引入。
2. 填写**候选矩阵**，逐项记录可借鉴点、冲突、理由和证据。
3. 分别写清**明确采纳**与**明确不采纳**的内容。
4. 基于上述记录更新 `decision`，不以来源存在代替评估结论。

## 落地

重新执行 `Q1-Q7`，再判定 `L1-L4` 并取得所需审批。之后按目标路径白名单确定目标路径和责任 PM，才可实施。进入 `implementation_ready` 前逐一核对来源绑定：`adopt` 只接受 `copy-internal-approved`，`adapt` 只接受 `adapt-internal-approved`，不得把其他 `reuse_scope` 推导成实施权限。完成后记录 `fresh 验证证据`，借鉴事项不得扩大来源权限或任何角色的写入权限。

## 审计

审计全程只读，以离线方式核对卡片、引用和证据；不联网、不执行来源内容、不刷新、不写卡片，最后运行 `P4t`。

## 关闭与失败

先核对关闭条件；`closure_seal_sha256` 不得手填、不得重算。关闭必须调用受信任入口 `能力资产/tools/scripts/close-borrowing-item.ps1`；该入口内部调用 `seal-borrowing-item.ps1` 并运行完整根 `P4t`，exit 0 后还必须持终锁复核正式卡的身份、长度与 sealed 字节，并在锁内清理本事务 staging，全部成功才输出 closed。参数和机器输出见[命令附录](借鉴-命令附录.md)，字段与事务不变量只以上述借鉴治理规则为准。

候选安装与 seal 提交都采用 no-overwrite，不覆盖任何后来对象。seal 返回后的材料若已绑定当前正式对象、仅 `borrow_id` 不一致，ownership 仍可证明，可按完整快照安全恢复原活动卡；其他 `seal-ownership-unproven` 分支必须保留当前正式卡与 staging。进入 `content-deleted` 不可逆完成点后不回滚正式卡。

### 关闭事务

| 关闭顺序 | 精确动作 | 失败边界 |
|---|---|---|
| 1 | 保留原活动卡字节 | 对外仍为原活动状态 |
| 2 | 构造 closed 候选 | 状态与历史写为 closed；closure_seal_sha256 为空 |
| 3 | 以 no-overwrite 装入候选并调用 seal-borrowing-item.ps1 | seal helper 失败不得宣称 closed；不得覆盖后来对象 |
| 4 | 运行根 P4t | exit 0 仅进入终锁复核；不得输出 closed |
| 5 | 持终锁复核并清理 staging | 身份、长度、sealed 字节稳定；删除两份 owned 内容后进入 content-deleted 不可逆完成点；目录清理成功才输出 closed |
| 可证明失败 | ownership 可证明且尚未进入 content-deleted 时恢复原活动卡；失败候选保留到被忽略 staging | 显式报告失败阶段与规范化路径；不得宣称 closed |
| 所有权不明或不可逆 | seal-ownership-unproven 保留当前正式卡与 staging；content-deleted 后不回滚正式卡 | 保留可审计残留并显式失败；禁止覆盖或猜测恢复 |

该事务同时适用于 adopt/adapt 与 reject；只有仍能证明正式对象由本事务拥有且尚未进入 content-deleted 才回滚；seal-ownership-unproven 或不可逆后的失败保留证据且不回滚正式卡。

失败时必须报告失败阶段、原因、`staging 路径`和恢复建议；不得宣称 ready，不得宣称 closed，也不得 reset、删除用户改动、覆盖后来对象或猜测性回滚。`seal-ownership-unproven` 与 `content-deleted` 后失败必须原样保留当前正式卡与 staging/可审计残留，交由人工核对。

零写入 preflight 失败：staging 输出固定为 `none（未创建）`。
仅在已有 staging 时输出其规范化路径。

## 固定输出

```text
【借鉴闭环】
事项：<borrow_id>｜状态：<status>｜决策：<decision>
来源：<source_id>@<capture_id>（<fingerprint>）
目标：<target files / none>
验证：<evidence / pending>
边界：未执行来源｜无业务直接依赖｜无外部写入
P4t：PASS / WARN / FAIL
```
