## Check 1: Are APK and smoke checks complete? (issue #1; strengthened by PROP-007 P1-2)

**Logic**: Compare the newest file timestamp in `{{APP_REPO_DIR}}/apk/` with the code-completion time of every F-XXX marked “⏳ Pending APK” in the current requirements lists or requirements history.
If the latest APK is newer than the code-completion time of any pending feature, ask whether F-XXX has already passed its smoke check.

**Required triggers** (PROP-007, narrowed to the current reactive boundary):
- Check at session startup, during release completion, when a pending APK/smoke status is observed, or when the user requests state inference.
- Do not force the check on every ordinary response. Track the recommendation until it is dismissed or confirmed complete; consult the decision table in `状态.md`.
- Ask: “F-XXX is still marked ⏳, but the latest APK is N days old. Has it already been tested?”
- If the user confirms, the responsible PM verifies the path allowlist, state rules, and evidence requirements before updating. If the answer is “not yet,” apply a seven-day cooldown.

```powershell
# Authoritative Windows/Codex entry: change to the current project root first.
Set-Location "{{PROJECT_ROOT}}"

# Latest APK timestamp
$latestApk = Get-ChildItem -LiteralPath "{{APP_REPO_DIR}}\apk" -Filter "*.apk" -File |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1
$latestApk | Select-Object FullName, LastWriteTime

# Pending APK features across all Sprint lists; do not hard-code Sprint-1.
Select-String -Path "Docs\1-需求文档\Sprint-*需求清单.md" -Pattern "^\| F-[A-Z0-9-]+.*⏳"
```

**Suggested output**:
```text
💡 Found {{APP_REPO_DIR}}/apk/{{PROJECT_NAME}}-vX.Y.Z-debug.apk (YYYY-MM-DD), but the current requirements list shows:
   - F-XXX status: ⏳ Pending APK
Has it been installed on the device and smoke-tested? Should the status change to ✅?
```

## Check 2: Do the documents reflect code changes? (issue #11)

**Logic**: Compare the latest file modification time in `{{APP_REPO_DIR}}/src` with the last requirements-history entry.
If the code modification time is more than one day newer, ask whether the requirements history needs updating.

The following history grep is a diagnostic example for legacy records. It does not validate current English requirements text. Use the authoritative `能力资产/tools/scripts/check-operating-system.ps1` checks and review the current requirements history.

```bash
# Latest file in {{APP_REPO_DIR}}/src
latest_code=$(find {{APP_REPO_DIR}}/src -type f \( -name '*.jsx' -o -name '*.js' \) -printf '%T@ %p\n' | sort -rn | head -1)

# Last requirements-history date: a rough search for the latest completed entry.
grep -E "✅.*已完成（[0-9]{4}-[0-9]{2}-[0-9]{2}" Docs/1-需求文档/需求历史.md | tail -1
```
