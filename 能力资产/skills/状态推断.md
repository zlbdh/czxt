# Skill: State Inference

Have the AI proactively reconcile documented state with actual conditions and identify status fields that should have changed but have not.

## When to run

- ⭐ Required at the start of a new implementation-loop session. Complete the five AGENTS startup steps first; this skill cannot replace that startup sequence.
- ⭐ Required before archiving a PROP as a mandatory DoD item.
- When zlbdh explicitly asks Mimi to run state inference.
- Midway through a long session, after 30+ interactions, to counter context drift.

## Difference from project health checks

| | Project health check | State inference |
|---|---|---|
| Focus | Framework consistency: headings, counts, broken links, large files | Progress reconciliation: code versus documentation |
| Output | Three-color report: ✅ / 🟡 / 🔴 | Recommendations such as marking an item ✅ or writing a RETRO |
| Frequency | Before PROP archiving or on request | Session startup, PROP archiving, release completion, or on request |

The skills complement each other: health checks assess documentation consistency; state inference checks whether the documents reflect actual progress.

## Check 10: 30-day freshness of 状态.md (added by PROP-017)

### Problem

The AI reads `状态.md` as its baseline at cross-session startup. A stale file, unchanged for more than 30 days, can distort decisions.

### Detection logic across runtimes

Authoritative entry: P4d in `能力资产/tools/scripts/check-operating-system.ps1`. Bash/GNU commands are fallbacks only; complete legacy examples are in the [monitoring appendix](状态推断-跨session监控-附录.md).

```bash
# Fallback: change to the current project root first.
cd "<project root>"

now=$(date +%s)
threshold=$(date -d '30 days ago' +%s)
mtime=$(stat -c %Y 状态.md 2>/dev/null)
[ -z "$mtime" ] && echo "🔴 状态.md is missing" && exit
days=$(( (now - mtime) / 86400 ))
[ "$mtime" -lt "$threshold" ] && echo "🟡 mtime is stale ($days days)" || echo "✅ mtime is $days days old"

latest=$(grep -oE '[0-9]{4}-[0-9]{2}-[0-9]{2}' 状态.md | sort -ru | head -1)
echo "Latest date in the content: $latest"
```

### Output format at AI startup

```text
🔍 Check 10 — 状态.md freshness
  mtime: 2026-05-12 (0 days ago) ✅
  Latest date in the content: 2026-05-12 (0 days ago) ✅
  → 状态.md is current and can be used as the baseline
```

If stale:

```text
🟡 Check 10 — 状态.md is 41 days stale
  → Update 状态.md before continuing; otherwise recommendations may rely on outdated information
```

### Relationship to PS1 P4d

- PS1 P4d uses Windows host facts and is authoritative.
- Check 10 reconciles the baseline at AI startup. Prefer PS1/host facts; use Bash/GNU only as a fallback.
- Both must use the same 30-day threshold and check both mtime and dates within the content.

---

## Known limitations

- Mount cache delay: mtime and file size seen through Bash may lag. Trust the Windows host values for verification.
- The AI is reactive: state inference runs only when the AI is triggered to respond. It is not a background daemon.
- Findings are recommendations, not determinations. Final decision authority remains with zlbdh. Inference alone does not authorize automatic status changes; write `状态.md` only after user confirmation or when required by PM tracking rules.

## Avoid repeated recommendations (added by PROP-006)

After generating a recommendation, check the recent recommendations and user decisions section of `状态.md`:
- Do not repeat the same recommendation if it was dismissed within the past seven days.
- If it is ⏳ pending, mention it once without repetition.
- Append a record under the state-file rules when the user explicitly decides and a record is required. Ordinary responses do not automatically update status fields.
