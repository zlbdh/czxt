# Skill: Run Tests

Run these checks after every major change. `Docs/4-测试文档/测试策略.md` defines the strategy; this document provides the commands.

## Current Windows / Codex recommendation

Core QA:

```powershell
cd {{PROJECT_ROOT}}\{{APP_REPO_DIR}}
npm test -- --run
npm run build
```

For Android / APK preparation, continue with:

```powershell
npx cap sync android
```

When an APK is needed, continue with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-apk.ps1
```

The `/tmp/mimi-*` sandbox steps below are only a fallback for the old Cowork environment.

## Run the complete set

```bash
WS="/sessions/<sandbox>/mnt/{{PROJECT_NAME}}/{{APP_REPO_DIR}}"
T=/tmp/mimi-test
B=/tmp/mimi-build

# Sync source into the test sandboxes
cp -rf "$WS/src/." "$T/src/"
cp -rf "$WS/src/." "$B/src/"

# Check syntax
cd "$T" && node syntax-check.mjs

# Run vitest
cd "$T" && npx vitest run

# Run vite build
cd "$B" && npx vite build
```

## First-time sandbox setup

```bash
T=/tmp/mimi-test
B=/tmp/mimi-build
mkdir -p "$T/src" "$B/src" "$B/public"

cd "$T"
cat > package.json <<'EOF'
{
  "name": "mimi-test",
  "type": "module",
  "scripts": { "test": "vitest run" },
  "devDependencies": { "vitest": "^4.1.5", "esbuild": "^0.25.0" }
}
EOF
cat > syntax-check.mjs <<'EOF'
import { transformSync } from 'esbuild';
import { readFileSync, readdirSync, statSync } from 'fs';
import { join } from 'path';

function walk(dir, files = []) {
  for (const name of readdirSync(dir)) {
    if (name === 'node_modules') continue;
    const p = join(dir, name);
    if (statSync(p).isDirectory()) walk(p, files);
    else if (/\.(js|jsx)$/.test(name)) files.push(p);
  }
  return files;
}
let ok = 0, fail = 0;
for (const f of walk('/tmp/mimi-test/src').sort()) {
  try {
    transformSync(readFileSync(f, 'utf8'), {
      loader: f.endsWith('.jsx') ? 'jsx' : 'js',
      target: 'es2020'
    });
    ok++;
    console.log(`  ✓ ${f.replace('/tmp/mimi-test/', '')}`);
  } catch (e) {
    fail++;
    console.log(`  ✗ ${f.replace('/tmp/mimi-test/', '')} → ${(e.errors?.[0]?.text || e.message).slice(0, 100)}`);
  }
}
console.log(`\n${ok} OK / ${fail} fail`);
EOF
timeout 38 npm install --no-audit --no-fund --silent

# Set up the build sandbox in the same way
cp -rf "/sessions/<sandbox>/mnt/{{PROJECT_NAME}}/{{APP_REPO_DIR}}"/{package.json,vite.config.js,tailwind.config.js,postcss.config.js,index.html} "$B/"
cp -rf "/sessions/<sandbox>/mnt/{{PROJECT_NAME}}/{{APP_REPO_DIR}}/public/." "$B/public/"
cd "$B"
timeout 38 npm install --no-audit --no-fund --silent
```

## Troubleshooting failures

### Syntax failures
- Check the line number.
- Suspect mount truncation? Run `wc -lc` and `tail -3`.
- Search for incorrect import names.
- Check for unclosed JSX tags.

### Vitest failures
- Read the test name and compare expected versus received values.
- If a new feature broke an existing test, fix the code or test according to the AC.
- If the new test itself is wrong, fix the test.

### Vite build failures
- For `Module not found`, add the required import.
- For `Cannot find package`, check for a missed npm dependency installation.
- For syntax warnings such as `Top-level await`, adjust the target.

## Add a new test

Create `src/shared/xxx.test.js`:

```js
import { describe, expect, it } from 'vitest';
import { fnUnderTest } from './xxx.js';

describe('fnUnderTest', () => {
  it('handles happy path', () => {
    expect(fnUnderTest(input)).toEqual(expected);
  });

  it('handles edge: null', () => {
    expect(fnUnderTest(null)).toBe(null);
  });

  it('handles edge: empty', () => {
    expect(fnUnderTest('')).toBe(null);
  });
});
```

Run:
```bash
cd /tmp/mimi-test
cp /sessions/<sandbox>/mnt/{{PROJECT_NAME}}/{{APP_REPO_DIR}}/src/shared/xxx.test.js src/shared/
npx vitest run src/shared/xxx.test.js
```

## Do not skip checks

- Run vitest even after a styling-only change; imports can still be wrong.
- Run vite build even if the previous build passed; dependencies may have changed.
- Run vite build even if all tests passed; production mode is stricter.
