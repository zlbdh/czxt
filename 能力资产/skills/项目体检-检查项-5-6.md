# Project Health Check — Checks 5–6

> Main entry: [Project health check](项目体检.md).
> Checks 1–4: [Basic checks](项目体检-检查项.md).

## Check 5 / 9: Cross-session synchronization

### Problem

Cowork, Claude Code, and Codex have independent sessions with no automatic communication channel. At completion, code or cards may be updated without synchronizing PRDs, history, or ADRs.

### Rules

- Every F-XXX marked ✅ completed in a current Sprint requirements list must have a corresponding requirements-history entry.
- Every PROP-XXX archive record in the requirements history must correspond to a PROP file under `已审批/已完成/`.
- Every ADR marked Current in the ADR README index must also have Current status in its file header.

### Commands

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-operating-system.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-readme-indexes.ps1
```

The handoff-zone checker covers only check 6. It does not verify Sprint lists against requirements history, PROP archiving, or ADR status consistency.

Bash/GNU fallback:

```bash
cd "<project root>"

echo "--- Sprint completed F-XXX set (all Sprint lists) ---"
grep -Eh "^\| F-[A-Z0-9-]+" Docs/1-需求文档/Sprint-*需求清单.md | grep "✅"

echo "--- Completed F-XXX set in requirements history ---"
grep -E "✅ \*\*F-[A-Z0-9-]+" Docs/1-需求文档/需求历史.md

echo "--- Draft ADRs (expect 0 unless drafting is in progress) ---"
grep -El "状态.*起草中|\*\*Status\*\*: Draft" Docs/3-开发文档/adr/ADR-*.md
```

### Exception

- “Pending APK and physical-device smoke” is a valid waiting state. The Sprint summary table must show ⏳ rather than ✅.

## Check 6 / 9: Handoff-zone health

### Rules

- At most three cards in `交接区/待接手/`.
- New pending handoff cards must include at least headings `## ①` through `## ⑥` in order. The `Status:` in section ⑤ must be one of `DONE / BLOCKED / HANDOFF / RISK / OBSERVE`.
- Recommend archiving accepted cards older than 30 days in `交接区/已接手/`. Automated checks prefer the filename date so that touching mtime does not falsely mark a card current.
- The top summary in `状态.md` must agree with the latest pending handoff card. If none are pending, the summary must say so.

### Command

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-handoff-zone.ps1
```

Bash/GNU fallback:

```bash
cd "<project root>"

handoff_count=$(ls 交接区/待接手/*.md 2>/dev/null | wc -l)
echo "Pending handoff cards: $handoff_count"
[ "$handoff_count" -gt 3 ] && echo "  🟡 Backlog (at most 3 is healthy)"

threshold=$(date -d '30 days ago' +%s)
for f in 交接区/已接手/*.md; do
  [ -f "$f" ] || continue
  mtime=$(stat -c %Y "$f")
  [ "$mtime" -lt "$threshold" ] && echo "  🟡 $f is older than 30 days; consider archiving"
done
```

### Assessment

- ✅ At most three pending cards, headings `## ①`–`## ⑥` complete and ordered, valid Status values, and no overdue cards.
- 🟡 More than three pending cards, missing or unordered base headings, a Status outside the five allowed values, or an accepted card older than 30 days.
- 🔴 The state summary links to a nonexistent card, or the pending card and summary contradict each other.
