## Check 7: Framework reference frequency (PS1 P4c)

### Problem

Markdown files in `操作系统/` and `能力资产/` can accumulate as the framework evolves. P4c uses reference frequency to identify unused content and potential orphan files.

### Thresholds

| References | Level | Meaning | Action |
|---|---|---|---|
| >= 10 | ⭐ Highly active | Framework backbone with many dependencies | Keep |
| 5–9 | ✅ Medium frequency | Stable reference | Keep |
| 2–4 | 🟢 Low frequency | Peripheral but still useful | Monitor; discuss at the next RETRO |
| 1 | 🟡 Very low frequency | Potential orphan | Evaluate consolidation |
| 0 | 🔴 Unused | No references | Remove or repair links through PROP governance |

### Scope

Active `操作系统/**/*.md` and `能力资产/**/*.md`. Reference sources include the framework, Docs, PROP, handoff zone, PM workspaces, and root entry points. Count the number of other Markdown files containing the filename; repeated references in the same source file count only once.

### Authoritative commands

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-operating-system.ps1
# Read P4c: framework reference frequency.

# Run P4c separately to inspect the Low 2–4 list manually.
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-os/p4c-framework-references.ps1 -ShowLowList
```

### Assessment

- ✅ No unused or very-low-frequency files is the healthiest result.
- 🟡 Evaluate every very-low-frequency file. Sample Low 2–4 entries with `-ShowLowList`, checking for missing natural entry points. Do not add artificial links just to improve counts.
- 🔴 One or more unused files requires action: remove them, correct their paths, or repair links.

## Check 8: 30-day freshness of 状态.md (PS1 P4d)

### Problem

`状态.md` is the central cross-session snapshot. P4d reconciles two dimensions:

| Dimension | Purpose |
|---|---|
| Filesystem mtime | Determine whether the file actually changed recently |
| Latest `YYYY-MM-DD` date within the content | Detect old content even if checkout or cloning reset mtime |

### Thresholds

| Dimension | <= 30 days | > 30 days |
|---|---|---|
| File mtime | ✅ | 🟡 Stale |
| Latest content date | ✅ | 🟡 Stale content |

Either dimension exceeding its threshold makes the snapshot stale. This is nonblocking, but a new session must first correct the state or run state inference.

### Authoritative command

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-operating-system.ps1
# Read P4d: 状态.md freshness.
```

### Assessment

- ✅ Both dimensions are at most 30 days old.
- 🟡 Either dimension exceeds 30 days: remind the Project PM to update it.
- 🔴 Missing file: already flagged by P4a baseline completeness.

Archive exception: if the project really has been inactive for 30 days, `状态.md` must explicitly say it is archived or paused. Manually dismiss the P4d warning afterward.

## Check 9: P4e mount-cache warning (issue D)

### Problem

When Cowork reads Windows host files through a Linux mount, `wc -c`, `ls -la`, and `stat` may report stale byte counts. Checking size with Bash immediately after a write can mislead decisions.

### Four defensive rules

| # | Rule | Trigger |
|---|---|---|
| ① | Verify warning/danger file sizes with Read instead of trusting Bash `wc -c` | Near 6500B / 8KB |
| ② | After Edit / Write / apply_patch changes a framework file, immediately read back its tail | Confirm the write took effect |
| ③ | Refresh the mount or restart the Cowork session if git status disagrees | Bash misses new files or shows an old diff |
| ④ | Trust PS1 byte counts in the P4b warning list instead of Cowork Bash | The numbers disagree |

### When Bash is reliable

- ✅ Read-only content searches without byte-level precision: grep, keyword lookup, and cross-file counts.
- ✅ Several minutes have passed across sessions and the mount cache has naturally expired.
- ❌ `wc -c` immediately after Edit / Write / apply_patch.
- ❌ Deciding whether a file exceeds a warning threshold; use PS1 plus Read instead.

### Authoritative command

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-operating-system.ps1
# Read P4e: mount-cache warning.
```

P4e is a nonblocking static reminder. It is a cross-session awareness safeguard, not an automatic repair tool.

## Additional guard: Active Markdown links and anchors (PS1 P4o)

P4o blocks broken links or missing anchors in active entry points: the framework, pending handoffs, entry README/governance indexes, PM workspace entries, root entries, and the current top section of `状态.md`. It runs through check-os and through the PostToolUse quick check in `check-readme-indexes.ps1`. Historical archives and older artifacts are not blocking; see the appendix for details.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-operating-system.ps1
# Read P4o: active relative Markdown links and anchors.

powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-os/p4o-markdown-links.ps1
```
