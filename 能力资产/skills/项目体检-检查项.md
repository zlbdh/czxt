## Check 1 / 9: Source-file size by tool (after PROP-013 / ADR-017)

### Tool-specific thresholds

**Cowork: mount truncation risk**

| Byte range | Status | Action |
|---|---|---|
| < 6000B | ✅ Safe | Edit and Write are both available |
| 6000–6500B | 🟡 Warning | Verify with Read before Edit; prefer Python/Bash for large-file writes |
| 6500–8000B | 🟡 Advisory | Cowork must use Python/Bash instead of Edit; a PROP is not mandatory |
| ≥ 8000B | 🔴 Danger: near the mount's 9KB hard truncation | Do not use Cowork Edit; hand off to Claude Code / Codex |

**Claude Code / Codex: local filesystem**

| Byte range | Status | Action |
|---|---|---|
| < 8KB | ✅ Safe | No restriction |
| ≥ 8KB | 🟡 Consider extracting components | Splitting by responsibility is an engineering recommendation, not an implementation blocker |

**Why thresholds differ by tool (PROP-013 / ADR-017)**: The 6500B threshold comes from Cowork's mount truncation risk. Claude Code / Codex do not have that write limitation; only the 8KB engineering recommendation applies.

### Explicit scope (added in health-check v26 after PROP-011)

| Scope | Applies? | Reason |
|---|---|---|
| `{{APP_REPO_DIR}}/src/` | ✅ Yes | Business code edited frequently; high mount truncation risk |
| `操作系统/` | ✅ Yes | Operating system rules frequently read and written by the AI |
| `能力资产/` | ✅ Yes | Hooks, skills, rules, and tools frequently read and written by the AI |
| `PM工作区/` | ❌ No size scan | Check entry state, nine PM directories/READMEs, and outdated conventions only; drafts, HTML, images, and PM self-correction history are not blocked by P4b size checks |
| `Docs/` | ❌ Exempt | Business PRDs, retrospectives, ADRs, and archives rarely change after completion |
| `确认改动/已审批/已完成/` | ❌ Exempt | Completed PROP records |
| `交接区/已接手/` + `**/历史归档/` + `agent-*-历史.md` | ❌ Exempt | Historical records |
| `交接区/待接手/` | 🟡 Boundary case | Short-lived files; below 6500B is recommended, not mandatory |

The check scans only active `.js/.jsx/.ts/.tsx/.md/.ps1/.json` files under `{{APP_REPO_DIR}}/src`, `操作系统`, and `能力资产`, excluding `状态-archive`, `CHANGELOG-2026*`, `历史归档/`, and `agent-*-历史.md`.

### Routine assessment

- Use current P4b output from `check-operating-system.ps1`. It summarizes `{{APP_REPO_DIR}}/src`, `操作系统`, and `能力资产` separately.
- Bash `wc -c` identifies candidates only. Important decisions require Windows host PS1 and Read verification.
- Occasional Bash scans and historical split notes are in the [checks 1–4 appendix](项目体检-检查项-1-4-附录.md).

## Check 2 / 9: PRD dual-source consistency

### Problem

PRDs often describe status in both tables and subsection headings. At completion, Claude Code may update a table while overlooking its subsection.

### Routine assessment

- The Sprint summary table and subsection heading must show the same state.
- A completed section must not retain “Pending X,” “TBD,” or “⏳” language.
- Manual grep templates are in the [checks 1–4 appendix](项目体检-检查项-1-4-附录.md).

### Exception

A feature genuinely awaiting APK or physical-device smoke checks after code completion may retain that pending wording. Its Sprint summary-table status must also be ⏳ rather than ✅.

## Check 3 / 9: PROP / ADR / RETRO count consistency

### Rules

- PROP count = pending approval + in progress + completed + deprecated + rejected.
- ADR numbers are contiguous, with no gaps.
- P4i/readme-index checks RETRO file/index consistency. Run `能力资产/tools/scripts/check-retro-cadence.ps1` for knowledge-retention cadence. The business L3+ count is a manual reference only; do not use the old fixed formula to derive RETRO numbers automatically.

### Comparison points

- Counts in `确认改动/README.md` must agree with actual directory file counts.
- Status values in the ADR README index must agree with each ADR header.
- Automated guards in `能力资产/tools/scripts/check-readme-indexes.ps1` and `能力资产/tools/scripts/check-operating-system.ps1` check all five PROP count columns, ADR README row counts, and meta-rule pool counts. Manual commands explain discrepancies only.
- Occasional diagnostic commands are in the [checks 1–4 appendix](项目体检-检查项-1-4-附录.md).

## Check 4 / 9: Legacy-path residue (prevent regression after ADR-007)

### Routine assessment

- Active documents must not refer to old top-level `rules/` or `agent/` paths as current sources of truth.
- Historical descriptions, migration maps, and archives may preserve the paths used at that time.
- Manual grep templates are in the [checks 1–4 appendix](项目体检-检查项-1-4-附录.md).

### Preserve historical records

- `rules/...` links in historical PROP/ADR/RETRO bodies are snapshots from when they were written; leave them unchanged under ADR-007 section C.
- `Agent/agents/`, `Agent/skills/`, and `Agent/workflows/` in ADR-003 / ADR-007 are migration mappings and historical descriptions of ADR-003/004/007 actions. They may remain.
- Old-path grep text inside the health-check skill is a diagnostic template, not a current source of truth.
