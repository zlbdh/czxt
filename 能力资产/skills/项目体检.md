# Skill: Project Health Check

Run periodically to find hidden problems: large files, conflicting PRD statuses, mismatched counts, legacy paths, missed cross-session updates, handoff backlogs, unused framework references, stale state, mount-cache errors, and broken active Markdown links.

This file keeps frequent-use entry points. Report templates and occasional commands are in the [health-check appendix](项目体检-附录.md).

## When to run

- Before every PROP archive, as required by the [implementation loop](../../操作系统/07_完整工作流/实施循环.md).
- When zlbdh requests a project health check.
- After major framework, hooks, or workflow changes.
- As a self-check at the end of a long session.
- When switching runtimes such as Cowork, Claude Code, or Codex, to close information gaps.

## Authoritative entry point

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 能力资产/tools/scripts/check-operating-system.ps1
```

The script is a facade over `check-os/` modules and covers P4a–P4t:

- P4b reports business-file maintenance under `{{APP_REPO_DIR}}/src`, grouping large files by test/production status and directory. The owner is the Development PM “Implementer.” Split files when functional work requires it, not merely to reduce counts to zero.
- P4o also enters the PostToolUse quick-check chain through `check-readme-indexes.ps1`, warning about broken active Markdown links after framework or PM workspace edits.
- P4p prevents old conventions from returning in shared / mcp / agents / workflows.
- P4q protects governance semantic anchors and the PROP state machine.
- P4r protects hooks configuration and scheduled/watch runtime anchors.
- P4s protects template-root neutrality. In addition to concrete project cards and known source-project keywords, it performs targeted current-truth checks on productization phases, development documents, dependency matrices, the brand glossary, and current playbooks. References must return to authoritative project-instance facts; source-project snapshots must not be presented as template facts.
- P4t performs read-only, offline validation of borrowing modes, source/item cards, states and closure conditions, path safety, and zero business-code dependencies.

In AGENTS startup instructions, “project health check” means this script's framework checks plus the separate [decision-checkpoint](../../操作系统/07_完整工作流/decision-checkpoint.md) Q1–Q7 self-check. Q1–Q7 is not embedded in the script; run it separately in the startup sequence.

In template-root mode, P4a also checks the copy inventory in `实例化项目.ps1`, ensuring Git installation or instantiation retains `项目区/`, `项目配置/`, `README.md`, runtime hooks configuration, and the governance layer.

Template-root mode applies when the root README identifies the repository as an operating system template and the scaffolding includes `项目配置/_模板.project.json` and `项目区/清单.md`. Project-instance-specific items receive reduced enforcement, including `Docs/1-需求文档/`, `TASKS.md`, source-project PROP bodies, and `{{APP_REPO_DIR}}/.git/hooks`. These checks become project gates again after instantiation into a real project.

- P4a: baseline completeness
- P4b: file size and business-file maintenance summary
- P4c: framework reference frequency
- P4d: state freshness
- P4e: mount-cache reminder
- P4f: PM transitions
- P4g: README/index consistency
- P4h: version/Sprint anchors
- P4i: governance counts
- P4j–P4t: guards for legacy conventions, branch strategy, skill-command freshness, PM workspace entries, active Markdown links, remaining capability areas, governance semantic anchors, hooks configuration, template neutrality, and borrowing closure consistency

## Known limitations

Verify actual files at important decision points instead of relying on a single Bash result:

- Mount cache delay: Bash `cat`, `tail`, `wc -c`, or `grep` may read cached content immediately after an edit.
- For split/threshold decisions based on `wc -c`, trust Windows host PS1 plus Read verification.
- Use `grep -a` if a Markdown file is treated as binary.
- `[ -z ]` can mislead when strings contain newlines; `wc -l` is more reliable for counts.

## Output colors

- ✅ Passed: no action.
- 🟡 Warning: near a threshold and nonblocking, but record it.
- 🔴 Failed: fix it before proceeding.

## Eleven health themes (script guards P4a–P4t)

| # | Check | Focus |
|---|---|---|
| 1 | Source-file size | Cowork: <6000B safe / 6000–6500B warning / 6500–8000B advisory / >=8000B danger; Claude Code/Codex: consider splitting responsibilities at >=8KB |
| 2 | PRD dual-source consistency | Completed sections must not retain “Pending X,” “TBD,” or “⏳” |
| 3 | PROP / ADR / RETRO counts | Table counts versus actual directories; guarded by readme-index and check-os |
| 4 | Legacy-path residue | Prevent old `rules/` or `agent/` references from becoming current sources of truth |
| 5 | Cross-session synchronization | Sprint lists versus requirements history and PROP archives |
| 6 | Handoff-zone health | At most three pending cards, complete base sections, archiving overdue accepted cards, and state-summary reconciliation |
| 7 | Framework reference frequency | No unused files; evaluate very-low-frequency files for consolidation; P4c |
| 8 | 30-day freshness of 状态.md | mtime and content dates; P4d |
| 9 | Mount-cache warning | Ten recorded incidents and four defensive rules; P4e |
| 10 | Template neutrality | No concrete project cards in the template root; no reintroduction of known source-project keywords; current entries remain template-neutral and point to authoritative project-instance facts; targeted P4s checks |
| 11 | Borrowing closure consistency | Read-only, offline validation of mode, source/item cards, state closure, paths, and zero business-code dependencies; P4t |
